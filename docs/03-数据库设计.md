# 03 · 数据库设计

> ⚠ 本文以 0.6.0「法元 · Faron」主版本为基线。**`feature/赛事版` 分支**为 `laws` 增加中文译名列（`title_zh` / `content_zh`）与 `laws_meta` / `country_intro` 元数据表——差异口径见 [11-赛事版改动说明.md](11-赛事版改动说明.md)。

> **同步至 0.6.0（2026-09-06；0.6.0 为品牌切换「法元 · Faron」，功能面同 0.5.0）**。本文档基于 `src-tauri/src/db.rs` 源码整理。数据库为 SQLite 单文件 `legal.db`，位于 `app_data_dir()` 目录（identifier 为 `com.legalworkbench.app`）。0.4.x 起共 11 张业务表 + 1 张 FTS5 虚拟表（`laws_fts`）+ 3 个同步触发器。

## 1. 连接与初始化

### 1.1 装载与初始化流程（`lib.rs::setup` + `db.rs::init`）

1. 定位数据目录并 `create_dir_all`。
2. **预置法库装载判定**：本地无 `legal.db`，或 `legal.db` 中 `laws` 仍只有播种示例（≤ 6 条，视为「从未导入过真实数据」的空库）时，从预置库 `legal_preload.db`（Resource / exe 同目录 / exe 旁浅层扫描 ≤ 3 层）拷贝装载；旧空库先备份为 `legal.db.user-<时间戳>.db` 再覆盖，保证老版本升级后自动获得内置法库。
3. 打开 `legal.db`，开启 PRAGMA：
   - `journal_mode = WAL`（写前日志）。
   - `foreign_keys = ON`（当前表结构未使用外键，聊天删除为命令内显式级联）。
4. 执行迁移 `migrate()`（幂等建表 / 补列 + 空表播种 + FTS5 索引维护）。
5. **密钥迁移**：把历史明文的 `ai.api_key` / `translate.api_key` 幂等加密落盘（`keycrypt.rs`）。
6. 连接以 `Mutex<Connection>`（类型别名 `DbState`）经 `app.manage()` 注入全局状态，命令内通过 `State<'_, DbState>` 获取，所有访问均需 `lock().unwrap()`。

### 1.2 迁移策略

`migrate()` 以 `CREATE TABLE IF NOT EXISTS` 幂等建表；历史版本缺列用 `ensure_column`（查 `PRAGMA table_info` 后 `ALTER TABLE ... ADD COLUMN`）幂等补齐。已存在的历史兼容迁移：

- `todos` 补 `last_notified_due`（记录已提醒的到期时间，避免重复弹窗）。
- `documents` 补 `file_path`、`kind`、`meta`（智能体交付物元信息）。
- `chat_messages` 补 `session_id`（旧消息归入 `id=0` 的「默认会话」，迁移时自动创建）。

> 说明：当前没有独立的 schema 版本号表，迁移由「幂等 DDL + 列存在性检查」驱动（见 [05-优化路线图.md](05-优化路线图.md) 的迁移版本化缺口）。

## 2. 表结构

### 2.1 settings —— 键值设置

存储 AI / 翻译接口、备份配置与偏好（「数据设置」版块）。

```sql
CREATE TABLE settings (
    key   TEXT PRIMARY KEY,
    value TEXT NOT NULL
);
```

写入采用 `INSERT ... ON CONFLICT(key) DO UPDATE SET value = excluded.value`（UPSERT）。常用键名（`src/hooks/useSettings.ts` 的 `KEYS` 常量）：

| 键 | 含义 | 备注 |
| --- | --- | --- |
| `ai.base_url` | AI 接口地址 | 如 `https://api.openai.com/v1` |
| `ai.api_key` | AI API Key | `enc:` 前缀密文落盘，读取时解密 |
| `ai.model` | 模型名 | 默认 `gpt-4o-mini` |
| `translate.provider` | 翻译引擎 | `free` / `paid` |
| `translate.api_key` | 付费翻译 Key | `enc:` 前缀密文落盘 |
| `translate.base_url` | 付费翻译接口地址 | 可空 |
| `backup.auto` | 自动备份开关 | `1` / `0`（**仅持久化配置，无定时调度**） |
| `backup.interval_days` | 备份周期（天） | 默认 `7` |
| `backup.target_dir` | 自动备份目录 | 可空 |
| `pref.default_popup` | 新待办默认桌面弹窗 | `1` / `0` |
| `fts.laws_count` | FTS5 重建时记录的 laws 条数 | 内部键，用于条数变化时重建索引 |

API Key 加解密规则见 `src-tauri/src/keycrypt.rs`（XOR + hex，`enc:` 前缀；与前端 `src/lib/secret.ts` 对称）。无前缀的旧值视为历史明文，启动时由 `migrate_secret_keys` 迁移为密文（幂等）。

### 2.2 laws —— 法律法规（法规查询 + 智能体检索数据源）

```sql
CREATE TABLE laws (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    title      TEXT NOT NULL,   -- 法规篇名，如《中华人民共和国民法典》
    chapter    TEXT,            -- 章节，如 第一编 总则
    article_no TEXT,            -- 条文号，如 第五百零二条
    content    TEXT NOT NULL,   -- 条文正文
    source     TEXT             -- 来源标注（内置示例 / e-Gov / govinfo / constitutioncenter 等）
);
```

要点：

- 数据规模：内置预置库装载后约 **152,940 条**（日本 95,897 + 美国 57,037 + 中国示例 6），正文体量约数百 MB；另有 6 条播种示例（仅当空表且未装载预置库时，见 §3.1）。
- 检索：`laws_search` 为**按需关键词检索**——空关键词返回空；关键词 ≥ 3 字且 FTS5 可用时走 `laws_fts`（BM25 相关度，先取 rowid 前 300 再回表按国家过滤，LIMIT 500），否则回退 `LIKE`（`title / content / article_no` 三列，LIMIT 500）。
- 国家判定 `country_sql()`：美国 = 标题以「美国法典 / 美利坚合众国宪法」开头或来源含 govinfo / constitutioncenter；中国 = 标题以「中华人民共和国」开头；日本 = 来源含 `e-gov.go.jp`；其余为「其他」。`laws_countries` 按该 CASE 分组计数；`laws_country_preview` 返回某国条文最多的前 8 部法规（title + 条文数）。
- Excel 导入（`import_excel`）写入本表；行级插入由触发器同步 FTS 索引。

### 2.3 templates —— 文书模板（模板库）

```sql
CREATE TABLE templates (
    id        INTEGER PRIMARY KEY AUTOINCREMENT,
    title     TEXT NOT NULL,    -- 模板标题
    category  TEXT,             -- 分类（授权文书 / 诉讼文书 / 劳动仲裁 / 函件 / 合同）
    content   TEXT NOT NULL,    -- 模板正文（____ 为待填项约定）
    file_type TEXT,             -- 文件类型，当前均为 txt
    built_in  INTEGER NOT NULL DEFAULT 0  -- 1=内置（不可删除），0=自建
);
```

内置模板 `built_in=1`，`templates_delete` 对内置模板返回错误「内置模板不可删除」；自建模板 `built_in=0`。Excel 导入的模板也写入本表（`built_in=0`）。

### 2.4 todos —— 待办提醒（待办版块 + 后台通知轮询）

```sql
CREATE TABLE todos (
    id                INTEGER PRIMARY KEY AUTOINCREMENT,
    title             TEXT NOT NULL,       -- 待办标题
    note              TEXT,                -- 备注
    due_at            TEXT,                -- 截止时间（RFC 3339 / ISO 8601 字符串）
    remind_minutes    INTEGER NOT NULL DEFAULT 0,  -- 提前提醒分钟数
    desktop_popup     INTEGER NOT NULL DEFAULT 1,  -- 是否桌面弹窗提醒
    done              INTEGER NOT NULL DEFAULT 0,  -- 是否完成
    created_at        TEXT NOT NULL,       -- 创建时间（RFC 3339）
    last_notified_due TEXT                 -- 兼容迁移补列：已提醒过的到期时间（防重复提醒）
);
```

要点：

- `desktop_popup`、`done` 用 0/1 存储，读取时映射为布尔。
- 后台线程（`lib.rs::check_todo_notifications`）每 30 秒轮询：`done=0 AND desktop_popup=1 AND due_at IS NOT NULL AND (last_notified_due IS NULL OR last_notified_due != due_at)`，凡 `due_at <= now + remind_minutes` 即发系统通知并回写 `last_notified_due`。
- 前端筛选（进行中 / 已超期 / 即将到期）在内存中计算；`todos_list` 仅按 `created_at DESC` 返回。

### 2.5 documents —— 最近文书（首页面板 + 智能体交付物落点）

```sql
CREATE TABLE documents (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    title      TEXT NOT NULL,
    content    TEXT,
    updated_at TEXT NOT NULL,          -- RFC 3339
    file_path  TEXT,                   -- 兼容迁移补列：交付文件路径（如导出的 .docx）
    kind       TEXT NOT NULL DEFAULT 'doc',  -- 兼容迁移补列：doc / docx / md 等
    meta       TEXT                    -- 兼容迁移补列：JSON 元信息（如 taskId、任务类型）
);
```

0.4.0 起由智能体交付物写入：`document_save`（`docx_export` 后由前端调用，`kind="docx"`、`file_path` 指向产物、`meta` 记 `taskId/kind`）；`documents_list` 按 `updated_at DESC LIMIT 200` 返回首页「最近处理的文书」；行内可「打开」或删除。

### 2.6 chat_sessions / chat_messages —— AI 问答会话

```sql
CREATE TABLE chat_sessions (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    title      TEXT NOT NULL,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL
);

CREATE TABLE chat_messages (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    session_id INTEGER NOT NULL DEFAULT 0,   -- 兼容迁移补列；旧数据（0）归入默认会话
    role       TEXT NOT NULL,                -- system / user / assistant
    content    TEXT NOT NULL,
    seq        INTEGER NOT NULL              -- 会话内顺序
);
```

要点：

- 会话删除 = 先删该会话全部 `chat_messages` 再删 `chat_sessions`（命令内显式级联）。
- `chat_history_save` 为「先清空再写入」（整体保存，与前端状态保持一致），并刷新 `chat_sessions.updated_at`。
- `chat_sessions_list` LEFT JOIN 消息表并 GROUP BY，返回消息数与最近更新时间排序。
- 前端浏览器预览下同一套结构降级到 localStorage（不落库）。

### 2.7 tasks / task_steps / task_artifacts —— 文书智能体任务状态机（0.4.0 新增）

```sql
CREATE TABLE tasks (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    kind       TEXT NOT NULL DEFAULT 'agent',  -- review / lawsuit / cross_exam 等
    title      TEXT NOT NULL,
    status     TEXT NOT NULL DEFAULT 'planned',-- planned / running / paused / done / failed
    context    TEXT,                           -- 任务输入材料
    plan_json  TEXT,                           -- 计划卡 JSON
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL
);

CREATE TABLE task_steps (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    task_id       INTEGER NOT NULL DEFAULT 0,
    seq           INTEGER NOT NULL,
    name          TEXT NOT NULL,
    tool          TEXT,          -- 工具名（空 = 推理步骤）
    params_json   TEXT,
    status        TEXT NOT NULL DEFAULT 'pending', -- pending / running / done / failed / waiting
    result_ref    TEXT,          -- 步骤结论 / 结果摘要（QA 步骤含确定性自检结论）
    need_confirm  INTEGER NOT NULL DEFAULT 0,      -- 1=需人工确认
    started_at    TEXT,
    updated_at    TEXT
);

CREATE TABLE task_artifacts (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    task_id    INTEGER NOT NULL DEFAULT 0,
    kind       TEXT NOT NULL,      -- docx / md 等
    file_path  TEXT,
    title      TEXT,
    content    TEXT,
    meta_json  TEXT,
    created_at TEXT NOT NULL
);
```

要点：

- `task_get` 返回 `{ task, steps, artifacts }` 组装结构（按 seq / id 排序）。
- `task_steps_save` 全量替换某任务的步骤（先删后插），返回新步骤 id 列表（计划卡确认后调用）。
- `task_delete` 级联删除 steps 与 artifacts。
- 历史任务支持载入续跑；首页「最近文书」与智能体交付物共用 `documents` + `task_artifacts` 双落点。

### 2.8 mem_vectors —— 智能体长期记忆（0.4.0 新增，P2）

```sql
CREATE TABLE mem_vectors (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    kind        TEXT NOT NULL DEFAULT 'task',  -- 记忆类型（当前 task）
    ref_id      INTEGER,                       -- 关联任务 id
    title       TEXT,
    content     TEXT,                          -- 记忆摘要文本
    vector_json TEXT,                          -- embedding（前端计算后回存 JSON 数组；无模型时为空串）
    created_at  TEXT NOT NULL
);
```

要点：embedding 由前端调用 `/embeddings` 计算后回存（`mem_save`），新任务发起时 `mem_list`（LIMIT 500）取出做向量 / 关键词召回并注入规划上下文（`agent.ts::recallMemory`）；浏览器预览降级到 localStorage（键 `workbench:mem`）。

### 2.9 laws_fts —— 法规全文索引（FTS5 虚拟表 + 触发器）

```sql
CREATE VIRTUAL TABLE laws_fts USING fts5(
    title, chapter, article_no, content,
    content='laws', content_rowid='id', tokenize='trigram'
);

-- 同步触发器（三件套）
CREATE TRIGGER laws_ai AFTER INSERT ON laws BEGIN
    INSERT INTO laws_fts(rowid, title, chapter, article_no, content)
    VALUES (new.id, new.title, new.chapter, new.article_no, new.content);
END;

CREATE TRIGGER laws_ad AFTER DELETE ON laws BEGIN
    INSERT INTO laws_fts(laws_fts, rowid, title, chapter, article_no, content)
    VALUES ('delete', old.id, old.title, old.chapter, old.article_no, old.content);
END;

CREATE TRIGGER laws_au AFTER UPDATE ON laws BEGIN
    INSERT INTO laws_fts(laws_fts, rowid, title, chapter, article_no, content)
    VALUES ('delete', old.id, old.title, old.chapter, old.article_no, old.content);
    INSERT INTO laws_fts(rowid, title, chapter, article_no, content)
    VALUES (new.id, new.title, new.chapter, new.article_no, new.content);
END;
```

要点：

- 外部内容表（`content='laws'`、`content_rowid='id'`），trigram 分词（对中日英无需空格的文本均可检索）。
- `ensure_laws_fts` 幂等创建；创建 / 重建失败只打日志，检索自动回退 LIKE，不影响主流程。
- 索引重建：`settings.fts.laws_count` 记录重建时的条数，启动迁移时若与当前 `laws` 条数不一致则执行 `INSERT INTO laws_fts(laws_fts) VALUES('rebuild')` 并更新计数（预置库 15 万条首次约数秒，一次性成本）。
- 查询侧用 `fts_phrase()` 把关键词转成引号包裹 + 转义的 MATCH 短语，防注入 / 语法冲突。

## 4. 备份与还原

- **手动备份**（`backup_now`）：把 `app_data_dir()/legal.db` 复制到用户指定目录，文件名为 `legal-YYYYMMDD-HHMMSS.db`。
- **还原**（`restore`）：用用户指定的备份文件覆盖 `legal.db`，成功后提示「还原成功，重启后生效」。
- 前端提示还原前先手动备份一次。

> 注意：备份 / 还原为文件级裸复制，不做 WAL checkpoint 与完整性校验（WAL 模式下如有未 checkpoint 数据，复制单文件可能不完整；当前规模下风险较低，文档如实标注该机制，见 [05-优化路线图.md](05-优化路线图.md)）。
>
> 另：升级时的「旧空库备份」会把空 `legal.db` 另存为 `legal.db.user-<时间戳>.db` 后再装载预置库。
