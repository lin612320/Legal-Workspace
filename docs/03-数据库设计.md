# 03 · 数据库设计

本文档基于 `src-tauri/src/db.rs` 源码整理。数据库为 SQLite 单文件 `legal.db`，位于 `app_data_dir()` 目录（identifier 为 `com.legalworkbench.app`）。

## 1. 连接与初始化

`db.rs::init(app_data_dir)` 完成：

1. 创建数据目录（`create_dir_all`）。
2. 打开 `legal.db`，开启 PRAGMA：
   - `journal_mode = WAL`（写前日志，提升并发读写表现）。
   - `foreign_keys = ON`（外键约束，当前表结构暂未使用外键）。
3. 执行迁移 `migrate()`（幂等建表 + 空表播种）。

连接以 `Mutex<Connection>`（类型别名 `DbState`）经 `app.manage()` 注入全局状态，命令内通过 `State<'_, DbState>` 获取，所有访问均需 `lock().unwrap()`。

## 2. 表结构

### 2.1 settings —— 键值设置

存储 AI / 翻译接口、备份配置与偏好，对应「数据设置」版块。

```sql
CREATE TABLE settings (
    key   TEXT PRIMARY KEY,   -- 设置键，如 ai.base_url
    value TEXT NOT NULL       -- 设置值
);
```

写入采用 `INSERT ... ON CONFLICT(key) DO UPDATE SET value = excluded.value`（UPSERT）。

常用键名（`src/hooks/useSettings.ts` 的 `KEYS` 常量）：

| 键 | 含义 | 示例值 |
| --- | --- | --- |
| `ai.base_url` | AI 接口地址 | `https://api.openai.com/v1` |
| `ai.api_key` | AI API Key | `sk-…` |
| `ai.model` | 模型名 | `gpt-4o-mini` |
| `translate.provider` | 翻译引擎 | `free` / `paid` |
| `translate.api_key` | 付费翻译 Key | `sk-…` |
| `translate.base_url` | 付费翻译接口地址 | 可空 |
| `backup.auto` | 自动备份开关 | `1` / `0` |
| `backup.interval_days` | 备份周期（天） | `7` |
| `backup.target_dir` | 自动备份目录 | `D:\法律备份` |
| `pref.default_popup` | 新待办默认桌面弹窗 | `1` / `0` |

### 2.2 laws —— 法律法规（版块 2）

```sql
CREATE TABLE laws (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    title      TEXT NOT NULL,   -- 法规篇名，如《中华人民共和国民法典》
    chapter    TEXT,            -- 章节，如 第一编 总则
    article_no TEXT,            -- 条文号，如 第五百零二条
    content    TEXT NOT NULL,   -- 条文正文
    source     TEXT             -- 来源标注（如 内置示例）
);
```

检索命令 `laws_search` 对 `title`、`content`、`article_no` 三列做 `LIKE '%keyword%'` 模糊匹配，结果按 `title` 排序。

### 2.3 templates —— 文书模板（版块 3）

```sql
CREATE TABLE templates (
    id        INTEGER PRIMARY KEY AUTOINCREMENT,
    title     TEXT NOT NULL,    -- 模板标题
    category  TEXT,             -- 分类（授权文书/诉讼文书/劳动仲裁/函件/合同）
    content   TEXT NOT NULL,    -- 模板正文（____ 为待填项）
    file_type TEXT,             -- 文件类型，当前均为 txt
    built_in  INTEGER NOT NULL DEFAULT 0  -- 1=内置（不可删除），0=自建
);
```

内置模板 `built_in=1`，`templates_delete` 对内置模板返回错误「内置模板不可删除」；自建模板 `built_in=0`。

### 2.4 todos —— 待办提醒（版块 6）

```sql
CREATE TABLE todos (
    id             INTEGER PRIMARY KEY AUTOINCREMENT,
    title          TEXT NOT NULL,      -- 待办标题
    note           TEXT,               -- 备注
    due_at         TEXT,               -- 截止时间（ISO 8601 字符串）
    remind_minutes INTEGER NOT NULL DEFAULT 0,  -- 提前提醒分钟数
    desktop_popup  INTEGER NOT NULL DEFAULT 1,  -- 是否桌面弹窗提醒
    done           INTEGER NOT NULL DEFAULT 0,  -- 是否完成
    created_at     TEXT NOT NULL       -- 创建时间（RFC 3339）
);
```

说明：

- 时间字段（`due_at`、`created_at`）存为字符串。创建时 `created_at` 由 Rust 侧 `chrono::Local::now().to_rfc3339()` 生成。
- `desktop_popup`、`done` 用 0/1 存储，读取时映射为布尔。
- 前端排序/筛选（进行中、已超期、即将到期）由前端在内存中计算；`todos_list` 仅按 `created_at DESC` 返回。

### 2.5 documents —— 最近文书（版块 1，预留）

```sql
CREATE TABLE documents (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    title      TEXT NOT NULL,
    content    TEXT,
    updated_at TEXT NOT NULL
);
```

**现状**：表已建，但没有任何读写命令与界面使用。首页「最近处理的文书」面板为占位，等待文书生成/导入功能接入。

## 4. 备份与还原

- **手动备份**（`backup_now`）：把 `app_data_dir()/legal.db` 复制到用户指定目录，文件名为 `legal-YYYYMMDD-HHMMSS.db`。
- **还原**（`restore`）：用用户指定的备份文件覆盖 `legal.db`，成功后提示「还原成功，重启后生效」。
- 前端提示还原前先手动备份一次。

> 注意：备份/还原操作直接复制文件，不校验数据库一致性；WAL 模式下如有未 checkpoint 的数据，复制单文件可能不完整（当前规模下风险较低，文档如实标注该机制）。

## 5. 浏览器预览的降级存储

非 Tauri 环境下不访问 SQLite，改用 `localStorage` 键：

| 键 | 对应表 |
| --- | --- |
| `workbench:laws` | laws（注入示例数据） |
| `workbench:templates` | templates（注入示例数据） |
| `workbench:todos` | todos |
| `workbench:settings` | settings |

浏览器模式下 `id` 用 `Date.now()` 生成，功能逻辑与桌面版保持一致。
