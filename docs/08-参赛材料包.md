## 一、一句话定位

**律政工作台 · 文书智能体**：一个跑在律师/法务本机上的"办案数字员工"——听懂委托 → 自主查 15 万条真实法条（内置日美法库）→ 起草并质检 → 交付可溯源、可双击打开的《法律文书/审查意见书》，全程数据不出本机。

## 二、作品创意描述（1 页版，可直接投稿）

我们面向法律工作者日常最重、最可外包的两件事——**审合同**与**写文书**，把产品从"AI 问答助手"升级为"能交付成果的数字员工"：

1. **任务理解**：粘贴合同/案情后，大模型先把模糊委托解析成结构化任务（条款范围、风险维度、检索关键词、步骤计划），并以"计划卡"呈现——人可改，改了照做。
2. **自主执行**：检索类步骤交给 **function calling 工具循环**——模型自己决定连续调用 `laws_search / law_by_id / template_load / translate_text`，每步结果回填再决定下一步；工具背后是本地内置的 15 万条日美法条文（来源 e-Gov / govinfo 官方），**只允许引用工具真实返回的法条**（附条文号与来源，可反查，防编造）。
3. **数字员工分工（多智能体接力）**：规划（拆任务）→ 检索员（召回法条）→ 起草员（生成文书）→ 质检员（核对引用真实性与覆盖度），界面可视化接力过程；关键步骤可设"人工确认闸门"，体现人在环上。
4. **结果交付**：一键生成《合同审查意见书 / 起诉状 / 质证意见》并**导出 .docx**，同时记入"最近文书"，可打开、可溯源、可直接二次编辑。
5. **记忆与检索增强**：长短期记忆分层（会话/任务档案/向量记忆），同类案件自动召回上次经验；法规检索接入 FTS5 全文索引，15 万条从"秒级 LIKE"走向"毫秒级 BM25"。
6. **工程形态**：Tauri 2 + React 单机应用（SQLite WAL），配套桌面悬浮球选词即用；未配置模型时进入演示模式，核心链路在浏览器预览即可跑通——**低门槛、可复现、可落地**。

**创新点一句话**：不是又一个"会聊天的法律助手"，而是把「真实法条引用 + 本地隐私 + 可验收文书交付」三者闭环的数字员工——这也是与通用问答类产品最本质的区别。

## 三、大模型环节流程（方案正文用）

| 环节 | 大模型做什么 | 输入 | 输出 | 调用工具/外部资源 | 防幻觉与约束 |
| --- | --- | --- | --- | --- | --- |
| ① 任务理解与规划 | 把模糊委托解析为任务 JSON（结构化输出） | 用户材料 + 任务类型 + 历史记忆（召回） | `title / steps[]`（步骤含工具、参数、是否人工确认） | 记忆召回（向量/关键词，可选） | 限制 3–8 步；解析失败回退预设流水线并明示"演示模式" |
| ② 工具决策与调用（循环） | 根据前序结果自主决定调用哪个工具、给什么参数 | 系统提示（角色=检索员）+ 上一步要点 | `tool_calls`（OpenAI 兼容协议） | `laws_search / law_by_id / template_load / translate_text` | 每步结果截断回填；最多 N 轮；只允许真实返回内容进入引用 |
| ③ 起草/合成 | 结合工具结果生成文书/意见段落 | 各步结果（证据）+ 角色提示（起草员） | 结构化文本（Markdown 子集） | 无 | 提示词强制"引用必须来自工具返回"；禁止编造条文号 |
| ④ 质检 | 核对引用真伪、覆盖度、口径一致性 | 草稿 + 引用清单 | 修正意见/补点 | `law_by_id` 复核（可选） | 二次调用 + 本地可反查校验 |
| ⑤ 成果交付 | 汇总为最终交付物（Markdown） | 全流程结果 | 交付物文本 | `docx_export`（零依赖 OOXML）→ 落 documents/任务归档 | 交付物内附"引用的法规条文"清单（篇名/条文号/来源） |
| （旁路）问答入口 | AI 问答：RAG 注入 + 多轮对话 | 用户提问 | 回答 + 一键"生成文书任务" | `laws_search`（问答内 RAG） | 转交文书智能体继续走 ①–⑤ |

## 六、商业模式（简述）

- **产品**：本地优先。基础版 = 法规检索/问答/翻译免费；增值 = "文书智能体"任务（审合同/起诉状/质证）按次或订阅。
- **客群**：律师与实习律师、企业法务、调解/仲裁辅助、法务外包团队。
- **企业/私有化**：律所、集团内网部署授权（本地库更新服务、文档模板定制、权限审计）。
- **生态延伸**：任务流水线模板可扩展至合规审查、人力/财税等垂直场景（模板化步骤引擎已支持新增"任务类型"）。

## 七、演示脚本（评审现场 90 秒版，可缩 60 秒）

1. **0–8 s 开场**：一句话定位（见 §一）+ 亮出已安装产品。
2. **8–25 s 任务理解**：文书智能体 → 填入示例合同 →「① 制定计划」→ 计划卡出现（模型驱动时由大模型生成，否则演示模式预设）。
3. **25–45 s 自主工具调用**：点「② 开始执行」，指着进度条数真实工具调用（≥3 次：`laws_search → law_by_id → template_load`…），强调"调用的是本地 15 万条真实法条"。
4. **45–60 s 引用溯源**：展示"本次引用法条"清单（篇名 + 条文号 + 来源），说明可反查、禁编造。
5. **60–80 s 可验收交付**：任务完成 → 预览意见书 →「导出 .docx」→「打开文件」（Word 打开）→ 回首页「最近文书」出现记录。
6. **80–90 s 收尾卖点**：全程本地运行、数据不出本机；多智能体接力与记忆一句话带过（详情见 PPT）。

## 九、答辩 Q&A 速答

- **Q：AI 幻觉/编法条怎么办？** A：双保险——① 引用只来自工具真实返回并附条文号+来源，可反查；② 质检角色二次核对 + 人工确认闸门。演示可直接反查给我们看。
- **Q：数据安全？** A：本地 SQLite，数据不出本机；API Key 混淆落盘（enc: 前缀），悬浮球侧同样处理；文档可演示删库即无痕。
- **Q：15 万条是日美法，中文呢？** A：中文按权威公开源全文导入（`docs/07` §八 有标准流程），评审现场以库内必命中词演示（§七 对照表）。
- **Q：商业模式/用户会付费吗？** A：先免费工具获客 → 任务按次/订阅 → 律所私有化；对价是"省 1–2 小时 × 高频周任务"。
- **Q：和大模型直接对话有什么区别？** A：本质差异三条——真实法条可溯源、本地隐私、可验收交付物；且流程可视化、人可介入。
- **Q：泛用性？** A：任务流水线 = 模板化步骤引擎，模板已支持"合同审查/起诉状/质证意见"，可低成本扩展新文书场景。
