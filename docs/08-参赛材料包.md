## 一、一句话定位

**律衡（Legal Workbench）· 文书智能体「小衡」**：一个跑在律师/法务本机上的"办案数字员工"——听懂委托 → 自主查 15 万条真实法条（内置日美法库）→ 起草并质检 → 交付可溯源、可双击打开的《法律文书/审查意见书》，全程数据不出本机。交付物引用经**确定性规则自检**（代码逐条比对"本次工具真实返回"，未覆盖自动点名），评审可当场反查。

## 二、作品创意描述（1 页版，可直接投稿）

我们面向法律工作者日常最重、最可外包的两件事——**审合同**与**写文书**，把产品从"AI 问答助手"升级为"能交付成果的数字员工"：

1. **任务理解**：粘贴合同/案情后，大模型先把模糊委托解析成结构化任务（条款范围、风险维度、检索关键词、步骤计划），并以"计划卡"呈现——人可改，改了照做。
2. **自主执行**：检索类步骤交给 **function calling 工具循环**——模型自己决定连续调用 `laws_search / law_by_id / laws_country_preview / template_load / translate_text`，每步结果回填再决定下一步；工具背后是本地内置的 15 万条日美法条文（来源 e-Gov / govinfo 官方），**只允许引用工具真实返回的法条**（附条文号与来源，可反查，防编造）。
3. **数字员工分工 + 确定性引用自检**：规划（拆任务）→ 检索员（召回法条）→ 起草员（生成文书）→ 质检员（核对引用真实性与覆盖度）接力，界面可视化；质检不靠模型"自述查过"——执行器用**代码级规则**把正文里的条文号引用（中文/日文「第X条（之Y/のY）」、美国法典「§NN」等格式）逐条与「本次工具真实返回」的法条比对，**未覆盖引用自动点名、提示人工核实，不计为有效引用**（这是与"二次调用纯 LLM 自查"类作品最本质的技术差异之一）。关键步骤可设"人工确认闸门"，体现人在环上。
4. **结果交付**：一键生成《合同审查意见书 / 起诉状 / 质证意见》并**导出 .docx**，同时记入"最近文书"，可打开、可溯源、可直接二次编辑；交付物为固定五段式——一、任务输入 / 二、执行过程与分步结果 / 三、引用的法规条文（可溯源）/ **四、引用自检（确定性规则校验）** / 五、结论——评审可当场抽查"任一引用是否都能反查到本次工具返回的法条"。
5. **记忆与检索增强**：长短期记忆分层（会话/任务档案/向量记忆），同类案件自动召回上次经验；法规检索接入 FTS5 全文索引，15 万条从"秒级 LIKE"走向"毫秒级 BM25"。
6. **工程形态**：Tauri 2 + React 单机应用（SQLite WAL），配套桌面悬浮球选词即用；未配置模型时进入演示模式，核心链路在浏览器预览即可跑通——**低门槛、可复现、可落地**。

**创新点一句话**：不是又一个"会聊天的法律助手"，而是把「真实法条引用 + 本地隐私 + 可验收文书交付」三者闭环的数字员工——这也是与通用问答类产品最本质的区别。**其中"引用反查"不是模型自述，而是交付物里代码级规则逐条核验的确定性结论**（未覆盖自动点名），评审可现场用反例验证。

## 三、大模型环节流程（方案正文用）

| 环节 | 大模型做什么 | 输入 | 输出 | 调用工具/外部资源 | 防幻觉与约束 |
| --- | --- | --- | --- | --- | --- |
| ① 任务理解与规划 | 把模糊委托解析为任务 JSON（结构化输出） | 用户材料 + 任务类型 + 历史记忆（召回） | `title / steps[]`（步骤含工具、参数、是否人工确认） | 记忆召回（向量/关键词，可选） | 限制 3–8 步；解析失败回退预设流水线并明示"演示模式" |
| ② 工具决策与调用（循环） | 根据前序结果自主决定调用哪个工具、给什么参数 | 系统提示（角色=检索员）+ 上一步要点 | `tool_calls`（OpenAI 兼容协议） | `laws_search / law_by_id / laws_country_preview / template_load / translate_text` | 每步结果截断回填；最多 N 轮；只允许真实返回内容进入引用 |
| ③ 起草/合成 | 结合工具结果生成文书/意见段落 | 各步结果（证据）+ 角色提示（起草员） | 结构化文本（Markdown 子集） | 无 | 提示词强制"引用必须来自工具返回"；禁止编造条文号 |
| ④ 质检 | 模型复核引用/覆盖度并给修改说明；QA 步骤产出末尾由执行器（代码）追加**确定性引用自检结论** | 草稿 + 本次工具真实返回（task.refs） | 复核意见 + 【引用自检 · 确定性规则】结论 | 无（自检为 `src/lib/agent.ts` 规则代码，必然执行） | 按中文/日文「第X条（之Y/のY）」、美「§NN」等格式识别正文条文号 → 逐条比对工具真实返回；未覆盖自动点名、不计有效引用（非纯 LLM 自查） |
| ⑤ 成果交付 | 汇总为最终交付物（Markdown，固定五段式） | 全流程结果 | 交付物文本 | `docx_export`（零依赖 OOXML）→ 落 documents/任务归档 | 交付物含"引用的法规条文"清单（篇名/条文号/来源）+「四、引用自检（确定性规则校验）」章节 |
| （旁路）问答入口 | AI 问答：RAG 注入 + 多轮对话 | 用户提问 | 回答 + 一键"生成文书任务" | `laws_search`（问答内 RAG） | 转交文书智能体继续走 ①–⑤ |

## 六、商业模式（简述）

- **产品**：本地优先。基础版 = 法规检索/问答/翻译免费；增值 = "文书智能体"任务（审合同/起诉状/质证）按次或订阅。
- **客群**：律师与实习律师、企业法务、调解/仲裁辅助、法务外包团队。
- **企业/私有化**：律所、集团内网部署授权（本地库更新服务、文档模板定制、权限审计）。
- **生态延伸**：任务流水线模板可扩展至合规审查、人力/财税等垂直场景（模板化步骤引擎已支持新增"任务类型"）。

## 七、演示脚本（评审现场 90 秒版，可缩 60 秒）

1. **0–8 s 开场**：一句话定位（见 §一）+ 亮出已安装产品。
2. **8–25 s 任务理解**：文书智能体 → 填入示例合同 →「① 制定计划」→ 计划卡出现（模型驱动时由大模型生成，否则演示模式预设）。
3. **25–45 s 自主工具调用**：点「② 开始执行」，指着进度条数真实工具调用（≥3 次：`laws_search → law_by_id → template_load`…），强调"调用的是本地 15 万条真实法条"。
4. **45–60 s 引用溯源 + 确定性自检**：展示"本次引用法条"清单（篇名 + 条文号 + 来源）与交付物「四、引用自检（确定性规则校验）」结论（识别 X 处 → 与工具真实返回对应 X/X），强调"代码逐条比对、非模型自查、未覆盖自动点名"。
5. **60–80 s 可验收交付**：任务完成 → 预览意见书 →「导出 .docx」→「打开文件」（Word 打开）→ 回首页「最近文书」出现记录。
6. **80–90 s 收尾卖点**：全程本地运行、数据不出本机；多智能体接力与记忆一句话带过（详情见 PPT）。

## 九、答辩 Q&A 速答

- **Q：AI 幻觉/编法条怎么办？** A：三道防线——① 全程只引用工具真实返回的法条（附条文号 + 来源，可反查）；② **确定性引用自检**：交付物合成与 QA 步骤收尾时，执行器用代码规则把正文条文号逐一与"本次工具真实返回"比对，未覆盖自动点名、提示人工核实（规则必然执行，不依赖模型"自查"）；③ 质检角色复核 + 人工确认闸门。评审可当场反查，也可现场埋一个库外条文号看自检点名。
- **Q：这个"自检"会不会只是模型说自己检查过？** A：不是。自检是 `src/lib/agent.ts` 里的确定性代码（`auditCitations` / `auditReport`）：按「第X条」/「§NN」等格式识别正文引用 → 与 `task.refs`（本次工具真实返回）比对 → 输出覆盖数并点名未覆盖项。是否执行、结论如何都与模型输出内容无关，评审可现场用反例验证。
- **Q：数据安全？** A：本地 SQLite，数据不出本机；API Key 混淆落盘（enc: 前缀），悬浮球侧同样处理；文档可演示删库即无痕。
- **Q：15 万条是日美法，中文呢？** A：中文按权威公开源全文导入（`docs/07` §八 有标准流程），评审现场以库内必命中词演示（§七 对照表）。
- **Q：商业模式/用户会付费吗？** A：先免费工具获客 → 任务按次/订阅 → 律所私有化；对价是"省 1–2 小时 × 高频周任务"。
- **Q：和大模型直接对话有什么区别？** A：本质差异——真实法条可溯源且经**确定性规则自检**（非模型自查）、本地隐私、可验收交付物；且流程可视化、人可介入。
- **Q：泛用性？** A：任务流水线 = 模板化步骤引擎，模板已支持"合同审查/起诉状/质证意见"，可低成本扩展新文书场景。
