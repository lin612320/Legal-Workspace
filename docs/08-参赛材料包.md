## 一、一句话定位

**法元（Faron）· 文书智能体「小元」**：一个跑在律师/法务本机上的"办案数字员工"，主场景为**涉外/跨境法律业务**——听懂委托 → 自主查 15 万条真实日美法条（内置 e-Gov / govinfo 官方法库，装机即用）→ 起草并质检 → 交付可溯源、可双击打开的《法律文书/审查意见书》，全程数据不出本机。交付物引用经**确定性规则自检**（代码逐条比对"本次工具真实返回"，未覆盖自动点名），评审可当场反查。中文全量法条按权威公开源接入为主版本后续路线图（dev 口径，赛事版不占用该规划；当前以内置示例 + 中文文书模板演示，口径如实）。

> **0.7.0 赛事版增量（2026-09-09，分支 feature/赛事版）**：① 文书智能体任务扩至 **5 类**（合同审查 / 起诉状 / 证据目录 / 质证意见 / 代理词，证据目录交付 .docx 原生表格）；② **知识图谱**：涉外案由人工策展种子 → 按材料命中案由 → 图谱「案由 → 构成要件 → 请求权基础 / 证据」骨架驱动**规划与编排** → 交付物叠加**法条适用性二段校验** → 任务命中法条自动登记候选边、**人工 ✓ / ✕ 确认后才作为规划依据**，Agent 页提供分层可视化图谱；③ **多模态材料输入**：DOCX / PPTX / XLSX / TXT / MD / CSV 本地离线提取，PDF / 图片走支持视觉/文件输入的模型（转录标注"非原文"；音频不在范围）。主叙事（本地隐私 + 确定性引用自检 + 端到端交付）不变，本增量不改变 0.6.0 赛事版口径已承诺的任何能力（详见 docs/11 §六）。

## 二、作品创意描述（1 页版，可直接投稿）

我们面向**涉外/跨境法律业务**中最重、最可外包的两件事——**审涉日/美合同**与**写涉外文书**（中日合资、赴美投资、跨境贸易与出口合规等场景），把产品从"AI 问答助手"升级为"能交付成果的数字员工"：

1. **任务理解**：粘贴涉外合同/案情后，大模型先把模糊委托解析成结构化任务（条款范围、风险维度、检索关键词与法域、步骤计划），并以"计划卡"呈现——人可改，改了照做。
2. **自主执行**：检索类步骤交给 **function calling 工具循环**——模型自己决定连续调用 `laws_search / law_by_id / laws_country_preview / template_load / translate_text`，每步结果回填再决定下一步；工具背后是本地内置的 15 万条日美法条文（来源 e-Gov / govinfo 官方），**只允许引用工具真实返回的法条**（附条文号与来源，可反查，防编造）。
3. **数字员工分工 + 确定性引用自检**：规划（拆任务）→ 检索员（召回法条）→ 起草员（生成文书）→ 质检员（核对引用真实性与覆盖度）接力，界面可视化；质检不靠模型"自述查过"——执行器用**代码级规则**把正文里的条文号引用（中文/日文「第X条（之Y/のY）」、美国法典「§NN」等格式）逐条与「本次工具真实返回」的法条比对，**未覆盖引用自动点名、提示人工核实，不计为有效引用**（这是与"二次调用纯 LLM 自查"类作品最本质的技术差异之一）。关键步骤可设"人工确认闸门"，体现人在环上。
4. **结果交付**：一键生成五类任务文书——《合同审查意见书 / 民事起诉状 / 证据目录 / 质证意见 / 代理词》（0.7.0 起，中文或对应语言输出，引用标注日/美法条原文号与来源）并**导出 .docx**（证据目录等表格型文书为 .docx 原生表格），同时记入"最近文书"，可打开、可溯源、可直接二次编辑；交付物为固定五段式——一、任务输入 / 二、执行过程与分步结果 / 三、引用的法规条文（可溯源）/ **四、引用自检（确定性规则校验）+ 四之二 法条适用性校验（知识图谱，0.7.0）** / 五、结论——评审可当场抽查"任一引用是否都能反查到本次工具返回的法条、并落在案由请求权基础范围内"。
5. **记忆与检索增强**：长短期记忆分层（会话/任务档案/向量记忆），同类案件自动召回上次经验；法规检索接入 FTS5 全文索引（BM25 相关度、短词自动回退 LIKE），15 万条按需检索不卡顿（实测耗时见验收记录，不预称"毫秒级"）。
6. **工程形态**：Tauri 2 + React 单机应用（SQLite WAL），配套桌面悬浮球选词即用（翻译 / 关联查找 / 预填任务材料）；未配置模型时进入演示模式，核心链路在浏览器预览即可跑通——**低门槛、可复现、可落地**。
7. **法域与语言可扩展**：检索词、法源国家（🇯🇵 / 🇺🇸）与文书输出语言按任务分流；中文全量法条按权威公开源（flk.npc.gov.cn 等）接入为后续版本路线图（接入流程见 docs/07 §八），当前以内置中文示例 + 中文文书模板演示——**边界如实，不夸大**。

**创新点一句话**：不是又一个"会聊天的法律助手"，而是把「真实法条引用 + 本地隐私 + 可验收文书交付」三者闭环的数字员工——这也是与通用问答类产品最本质的区别。**其中"引用反查"不是模型自述，而是交付物里代码级规则逐条核验的确定性结论**（未覆盖自动点名），评审可现场用反例验证。

## 六、商业模式（简述）

- **产品**：本地优先。基础版 = 法规检索/问答/翻译免费；增值 = "文书智能体"任务（涉日/美合同审查、起诉状、证据目录、质证意见、代理词五类，0.7.0）按次或订阅。
- **客群**：涉外/跨境业务律师与实习律师、涉外企业法务与合规岗、出口管制与贸易合规团队、法律翻译/研究与仲裁调解辅助、法务外包团队。
- **企业/私有化**：律所、涉外集团内网部署授权（本地库更新服务、文书模板定制、权限审计）。
- **生态延伸**：任务流水线模板可扩展至合规审查、人力/财税等垂直场景（模板化步骤引擎已支持新增"任务类型"与法域）。
- **成本结构与定价逻辑**（完整页见 §十一-C）：本地零边际存储 + 任务按 token 计价；示例定价与"省 1–2 小时 × 律师小时费率"的对价关系；不虚构竞品价格实证，答辩只做定性。

## 七、演示脚本（评审现场 90 秒版，可缩 60 秒）

1. **0–8 s 开场**：一句话定位（见 §一）+ 亮出并打开赛事版「法元」（`发布包/法元_0.6.0_赛事版_x64-setup.exe` 装机演示）。
2. **8–25 s 任务理解**：文书智能体 → 填入**涉日合资/赴美投资示例合同** →「① 制定计划」→ 计划卡出现（模型驱动时由大模型生成；未配置模型时**先口头声明一句**："当前未配置模型接口，走演示模式——计划为预设流水线，但工具调用真实执行"，随后照常演示）。
3. **25–45 s 自主工具调用**：点「② 开始执行」，指着进度条数真实工具调用（≥3 次：`laws_search → law_by_id → template_load`…），强调"调用的是本地 15 万条真实日美法条（e-Gov / govinfo）"，检索词用库内必命中词（日本 `契約 / 民法`、美国 `trademark`）。
4. **45–60 s 引用溯源 + 确定性自检**：展示"本次引用法条"清单（篇名 + 条文号 + 来源）与交付物「四、引用自检（确定性规则校验）」结论（识别 X 处 → 与工具真实返回对应 X/X），强调"代码逐条比对、非模型自查、未覆盖自动点名"。
5. **60–80 s 可验收交付**：任务完成 → 预览意见书 →「导出 .docx」→「打开文件」（Word 打开）→ 回首页「最近文书」出现记录。
6. **80–90 s 收尾卖点**：全程本地运行、数据不出本机；涉外主场景 + 中文法库路线图一句话带过（"中文全量法条按权威公开源接入在路上，当前中文以示例与文书模板演示"）；多智能体接力与记忆可并入 PPT。

> 拍摄前按 `docs/07` §七 关键词对照表选库内必有命中的演示词，避免"0 命中"翻车。
> 加分演示（建议先在本机自验再上现场）：在计划卡埋一个"库内不存在条文号"的引用，展示 QA 日志 / 交付物「四」自动点名——反例比顺例更能证明自检是硬校验而非模型自述。
> 如需强化"法库"画面：在第 1–2 步之间插入约 10 s——「法规查询 → 按法浏览 → 🇯🇵 日本 → 打开『日本国憲法』→ 输入条文号跳转 → 打开『美国宪法』看官方中译」，双语 / 整法 / 条文跳转 / 译文一镜带过。

## 九、答辩 Q&A 速答

- **Q：AI 幻觉/编法条怎么办？** A：三道防线——① 全程只引用工具真实返回的法条（附条文号 + 来源，可反查）；② **确定性引用自检**：交付物合成与 QA 步骤收尾时，执行器用代码规则把正文条文号逐一与"本次工具真实返回"比对，未覆盖自动点名、提示人工核实（规则必然执行，不依赖模型"自查"）；③ 质检角色复核 + 人工确认闸门。评审可当场反查，也可现场埋一个库外条文号看自检点名。
- **Q：这个"自检"会不会只是模型说自己检查过？** A：不是。自检是 `src/lib/agent.ts` 里的确定性代码（`auditCitations` / `auditReport`）：按「第X条」/「§NN」等格式识别正文引用 → 与 `task.refs`（本次工具真实返回）比对 → 输出覆盖数并点名未覆盖项。是否执行、结论如何都与模型输出内容无关，评审可现场用反例验证。
- **Q：数据安全？** A：本地 SQLite，数据不出本机；API Key 混淆落盘（enc: 前缀），悬浮球侧同样处理；文档可演示删库即无痕。
- **Q：15 万条是日美法，中文呢？** A：主场景是**涉外/跨境日美法务**——审涉日/美合同本就该引用日本法 / 美国法典原文（本地内置官方法条，可溯源）；中文全量法条按权威公开源（flk.npc.gov.cn 等）接入是既定路线（`docs/07` §八 有标准流程），当前中文以内置示例 + 中文文书模板演示，评审现场用库内必命中词（§七 对照表）。
- **Q：面向国内评审，为什么先做涉外？** A：本地库 15 万条日美官方法条是当前差异化资产，涉外/跨境是数据与能力最自洽的场景；产品是"法域可扩展的平台"——中文法条接入后同一套智能体流程零改动服务国内场景（路线图）。
- **Q：商业模式/用户会付费吗？** A：先免费工具获客 → 任务按次/订阅 → 律所私有化；对价是"省 1–2 小时 × 高频周任务"，成本侧本地零边际存储、任务按 token 计价（详见 §十一-C）。
- **Q：和大模型直接对话有什么区别？** A：本质差异——真实法条可溯源且经**确定性规则自检**（非模型自查）、本地隐私、可验收交付物；且流程可视化、人可介入。
- **Q：泛用性？** A：任务流水线 = 模板化步骤引擎，模板已支持"合同审查/起诉状/质证意见"，可低成本扩展新文书场景。

### D. 创意描述（报名表粘贴版 · 含大模型环节流程细节）

> 规则要求创意描述包含"使用大模型的环节流程细节"——本段为自包含成品（约 900 字），可直接整段粘贴进报名表"作品创意描述"，再按表格字数限制增删。

**作品名称**：法元 · 文书智能体「小元」——本地化涉外办案数字员工

**创意概述**：面向律师与企业法务，我们把"AI 法律助手"升级为**能交付可验收成果的数字员工**。用户把一份涉日/美合同或案情委托交给"小元"，它会听懂委托、制定并展示可编辑的计划卡，自主调用本地工具检索内置的 15 万条真实日美法条（e-Gov / govinfo 官方来源），起草《合同审查意见书 / 起诉状 / 质证意见》并质检，最终交付可溯源、可双击打开的 .docx 文书。全程数据不出本机，引用真实可反查。

**大模型环节流程细节**（共五环 + 旁路）：
- ① **任务理解与规划（LLM 结构化输出）**：把用户输入的合同/案情文本解析为任务 JSON——意图、条款范围、风险维度、检索关键词与法域、3–8 步执行计划；解析失败自动回退预设流水线并明示"演示模式"。
- ② **工具决策与调用循环（LLM function calling）**：检索类步骤由模型在多工具间自主决策连续调用 `laws_search / law_by_id / laws_country_preview / template_load / translate_text`，每步真实结果截断回填、模型据此前序结果决定下一步，直至给出结论；单步超时、最多 N 轮、异常暂停，关键步骤可设"人工确认闸门"。
- ③ **起草/合成（LLM + 检索证据）**：结合工具真实返回的法条起草文书段落；提示词强制"引用必须来自工具返回"，禁止编造条文号。
- ④ **质检（LLM 复核 + 代码级确定性自检）**：质检角色复核引用真实性与覆盖度并给修改说明；与此同时，**执行器用代码规则**（非模型自查）把正文条文号（中文/日文「第X条（之Y/のY）」、美国法典「§NN」等格式）逐条与"本次工具真实返回"比对，未覆盖项自动点名、提示人工核实、不计为有效引用——结论写进交付物固定章节「四、引用自检（确定性规则校验）」，评审可当场反查或埋反例验证。
- ⑤ **成果交付（本地生成）**：汇总为固定五段式交付物 → 一键导出 .docx（零依赖 OOXML 生成器）→ 可打开/定位/二次编辑 → 记入"最近文书"与任务档案；浏览器版导出 .md。
- （旁路）**咨询→交付**（赛事版口径）：已移除独立「AI 问答」栏——即时咨询由悬浮球面板「询问 AI」完成；要交付成果时直接把合同/案情粘贴给「小元」即可走 ①–⑤。悬浮球在任何应用划词可预填任务材料。

**创新点与差异化**：① 真实法条引用可反查（本地 15 万条官方法条、附条文号与来源）；② **确定性引用自检是代码级规则逐条对账，不是模型"自述查过"**——未覆盖自动点名，评审可当场用反例验证；③ 本地隐私 + 可验收交付（.docx）端到端闭环，断网可演示；④ 数字员工按"规划/检索员/起草员/质检员"角色接力并可人工介入，流程可视化可管可控。当前内置日美法库开箱即用，中文全量法条按权威公开源接入为后续版本路线图，产品本身是"法域 × 文书场景"可扩展平台。
