## 一、项目概述

### 1.1 背景与定位

法律从业者（律师、法务、调解员等）日常工作高度依赖"查法规、写文书、问 AI、译外文"，而现有工具分散在浏览器 / 翻译器 / 通用 AI 之间，数据与上下文割裂；通用 AI 回答无法保证法条真实可溯源，云端产品又存在敏感数据出网风险。

**法元**（工程名：legal-workbench，历史名：律政工作台 → 律衡，英文 Faron）是一个本地优先的法律工作一体化应用：把「法规库 + 文书智能体（小元）+ AI 问答 + 翻译 + 悬浮球选词」收进一个单机应用。**数据全在本机**，敏感文书不出内网；内置日美法库（152,940 条条文，来源 e-Gov / govinfo 官方）开箱即用——**主场景定位于涉外/跨境法律业务**：审阅涉日本、美国法律关系的合同与文书（中日合资、赴美投资、出口管制合规等），「文书智能体「小元」」可自主查真实法条、起草并交付 .docx 文书——形成"听懂委托 → 制定计划 → 自主调用工具 → 交付可溯源成果"的端到端闭环（数字员工）。中文全量法库列入 0.7.0 路线图（按权威公开源接入，禁止编造条文，见 docs/07 §八）；当前中文能力以内置示例法条 + 中文文书模板演示。**0.8.0 规划（方案稿）**：借鉴联邦学习"数据不动、模型动"的范式，让「小元」在保持"数据不出本机"前提下实现自进化（联邦配方进化，docs/12）。

### 1.2 品牌与视觉识别（Logo 与设计理念）

品牌口径：中文名「**法元**」（取"法"之专业与"元"之根本/元数据）、英文名「**Faron**」；**0.6.0 起由「律衡」正式切换为「法元 · Faron」**。工程名 / 主程序 exe / 进程 / `identifier` / 数据目录（`legal-workbench`、`com.legalworkbench.app`）保持不变，升级不丢数据。

**品牌标志（Logo）与设计理念**——原始表述见仓库根 `logo设计理念.txt`，图形见 `logo.jpg`；成套图标由 `scripts/make-icons.ps1` 从该标志复跑生成。

![图 1　法元 · Faron 品牌标志（红色渐变几何字标，所有图形单元由平行四边形构成）](../logo.jpg "2.4in")

| 设计元素 | 传达的意思 | 落到产品上的解释 |
| --- | --- | --- |
| **红色** | **中国品牌** | 红色是中国品牌最直接的视觉表达（亦与法律印章的中国红相合）。法元服务中国法律工作者，用正红立品牌立场——第一眼就知道"这是给国内法律人的产品" |
| **渐变** | **智能、科技** | 由单一平色改为**红色渐变**：明暗与方向的变化让静态标志带上"运行中"的观感，对应产品由大模型驱动的智能化与科技属性 |
| **平行四边形** | **高效、利落** | 标志的**所有图形单元（笔画）全部由平行四边形构成**，不含曲线与多余装饰。几何上的利落，对应产品一向的工程性格：规则级校验、分步执行、不拖泥带水 |

> **一句话记忆点**：用**中国红**讲清"我是谁"，用**渐变**讲清"我由 AI 驱动"，用**平行四边形**讲清"我干活利落"。

**视觉规范（依据标志实测）**：

- **主色**：品牌红渐变 **#EA0202（亮红）→ #8C1012（深红）**，取色自 `logo.jpg` 的色域（标志中心亮、边缘沉），全套物料以此为准；
- **底色与图标形态**：标志原底为**白色**；应用图标采用**白色圆角方块 + 居中标志**（圆角半径 ≈ 边长 18%、四周内边距 ≈ 12%）。保留白底而不做透明抠图，是为了在**日间/夜间两种主题与深浅两类任务栏**下都维持对比度（深色底上红色暗部会"沉"进背景）；圆角形态与旧版「渐变圆角 + 字标」的图标语言保持一致，属"换标志不换气质"；
- **缩放纪律**：一律等**比缩放**，禁止拉伸变形；小尺寸（16 / 24 px）保留标志整体轮廓，不做简化重绘或换字；
- **单一来源**：所有图标与页面用图**均由 `logo.jpg` 一个源文件生成**——新增脚本 [`scripts/make-icons.ps1`](../scripts/make-icons.ps1) 可复跑（生成桌面图标全套、多尺寸 ICO、演示站内嵌底图），杜绝"标志一个样、图标另一个样"的视觉漂移；
- **使用边界**：标志不叠加投影 / 描边 / 其它渐变，不与其它品牌标志并排混用；对外物料优先使用白底版本。

### 2.1 明确不做（边界；0.6.0 口径 + 0.7.1 补充）

- 云账号 / 多端同步 / 多人协作（本地优先是产品定位，不是缺陷）；

- 移动端全量离线法库（490 MB 不适合手机默认分发）；
- 法规语义向量检索入口（15 万条不适合一次性全量 embedding，采用 FTS5 关键词召回 → Top 结果喂模型）；
- docx 复杂版式（表格化风险清单、批注修订版）——当前为最小 OOXML 子集；
- 自动备份定时调度（仍为配置 + 手动执行）；
- **联邦配方进化（0.8.0 规划，方案稿）**：默认关闭、opt-in；**不做**上传任何用户原文 / 文书 / 密钥，**不做**"联邦大模型权重"（模型走 API 无本地权重，联邦对象为编排配方，docs/12 §1.3 / §3.3）。
- **0.7.1 起移除**：内置免费翻译接口（Google gtx 通道，国内网络不可达且译文不可控）——翻译不再有独立通道，一律复用用户自配的 AI 接口；不提供"翻译历史 / 术语表 / 逐段对照"（列入 §6.1 候选）。
- **不做云端托管演示**：演示站为纯静态单页（功能展示 + 交互演示），不上传用户数据、不代管 API Key；真实功能体验仍以桌面安装包为准（数据不出本机是产品定位）。

## 三、用户场景与价值

1. **审涉日/美合同（端到端主场景）**：粘贴涉日合资、赴美投资、跨境贸易/出口合规类合同 → 文书智能体制定计划 → 自主检索本地内置的真实日美法条 → 起草《合同审查意见书》（中文输出，引用日美法条原文号 + 来源）→ 导出 .docx、引用可反查。
2. **写涉外文书**：起诉状 / 质证意见一键流水线，模板 + 法条双支撑，产出可二次编辑；检索词、法源、文书语言可按"涉日 / 涉美"分流。
3. **问 AI 要依据**：AI 问答注入真实法条，回答"引真条、不编造"；可一键"生成文书任务"转交智能体。
4. **查外法**：涉外业务查日本法 / 美国法典——"遺留分""trademark"国家内秒级命中，出处可标注（FTS5）。
5. **选词即用**：悬浮球在任意应用划词 → 翻译 / 关联查找（走主程序本地法库检索）/ 预填任务材料。
6. **中文法务延伸（路线图，0.7.0）**：接入中文全量法条后，同一套智能体能力服务于国内审合同 / 劳动纠纷等场景；当前中文以内置示例法条 + 中文文书模板演示。
7. **外出移动**：开庭 / 出差途中查法条、AI 摘要（移动端演示版）。
8. **智能体随使用自进化（0.8.0 规划·方案稿，docs/12）**：用户对计划卡的手工调整、检索命中与 0 命中、引用自检结果等本地日志，经匿名化聚合后回传"更好配方"——用户越多、任务越多样，「小元」默认流水线、检索词典与质检阈值越好用；同时聚合的需求缺口（0 命中词、新增任务类型分布）驱动产品路线排期（新法域、新文书模板、中文法库优先级）。

### 市场与商业可行性论证（参赛口径，对应评分项"市场可行性"）

**目标用户与使用价值（泛用性论证）。** 首批用户为三类高付费、强刚需人群：①涉外/跨境业务律师（中企出海、赴日美投资、跨境贸易/出口管制合规逐年增多，涉日美合同与文书审查是高频刚需）；②企业法务与合规岗（审阅涉外条款、翻译外国法原文、内部合规审查）；③法律研究与翻译岗。产品把"查法规、写文书、问 AI、译外文"四类散落工具收进一个单机应用，并给出通用 AI 与云端 SaaS 给不了的两点：**法条真实可溯源（不编造）+ 敏感文书不出网**。

**"窄市场"质疑的回应——法律域无关的可复制引擎。** 智能体管线（任务理解 → 规划 → 工具调用 → 质检 → .docx 交付）与法律域**解耦**：内置日美法库只是第一份"数据资产"，更换/扩充法库即可覆盖新场景。路线图已排定中文全量法库（0.7.0，docs/07 §八）——接入后同一套能力直接服务国内审合同、劳动仲裁、知产合规等更广阔市场；对律所/企业还可做**私有法库定制**（导入所内文书模板与常用法规）。因此"涉外日美"是**验证期聚焦场景**，不是能力上限。

**商业价值与盈利模式落地路径。** 三层结构：①免费基础层（法规浏览/检索、翻译、悬浮球划词）用于获客与建立信任；②任务订阅/按次层（数字员工执行合同审查、起诉状、质证意见——按次或订阅计费）；③企业私有化部署授权（律所/出海集团内网部署、法库更新服务、模板定制、操作审计——年费制）。定价锚点：一次审合同任务 ≈ 律师 1–2 工时，定价天花板取工时成本的小部分，地板取任务 token 成本；相比人工与云端 SaaS 均有明确价值空间。本地优先同时构成数据合规卖点（涉密文书不出内网），是律所/企业采购的关键决策因素。**0.8.0 规划的增值点**：企业私有化联邦域（所内聚合、越用越懂本所业务）与跨所匿名进化（docs/12 §6.3）可作为私有化授权档的续费理由与差异化能力。（**客户细分 / 定价 / 三年财务口径以 §九为准**，本节为赛道评审口径，两者视角不同、互为对照。）

**竞争优势与短板（诚实口径）。** 对比通用 AI 对话（无法条溯源、数据出网）与云端合同审查 SaaS（数据托管、无法条级溯源）：本作的差异点是"真实法条内置可溯源 + 引用经确定性规则自检 + 交付 .docx + 核心能力离线可用"。短板：无账号/协作/生态、无销售渠道与品牌、涉外场景市场教育成本高——属商业化阶段的工程量问题而非技术障碍，详见第八章风险对策。

## 五、技术方案

### 5.1 桌面端（现状）

Tauri 2（Rust）+ React 18 / TS + Vite 5 + SQLite（rusqlite bundled，WAL）；`laws_fts`（FTS5）；零依赖 OOXML docx 生成（`docx.rs`）；API Key XOR+hex 混淆（`keycrypt.rs`，启动迁移明文）；Electron 33 悬浮球；NSIS 打包（内嵌悬浮球与预置库）；双环境降级（桌面 SQLite / 浏览器 localStorage）。

**0.7.x 新增实现要点**：`office.rs` 办公文档本地文本提取（手写最小 ZIP 读取 + flate2，零外部转换服务）；`extract_material_b64` 命令（前端文件选择器只有字节、拿不到绝对路径，故按"文件名 + base64"临时落盘解析后立即删除）；翻译链路 `lib/translate.ts`（单通道 AI 接口 + 长文分段 + 流式）/ `lib/translateDoc.ts`（文档导入与译文导出）/ `lib/multimodal.ts`（PDF 与图片交模型转录，`lib/ai.ts` 提供多模态 content parts）；待办 SQL 收敛至 `db.rs`（`todo_create / todo_save / todo_update / todo_delete / todo_mark_notified`），布尔列统一经 `flag()` 显式写 0/1，底层报错经 `friendly_db_err` 转为可读中文；渲染层 `invokeStrict` 让写入类操作失败可见（不再被 `callRust` 静默吞掉）。

**0.7.3 品牌资产实现要点**：图标不引入图形库，用 `scripts/make-icons.ps1`（PowerShell + System.Drawing）从 `logo.jpg` 生成——① 自动扫描非白像素求标志外接框（397×387 @ 55,54）；② 以 `GraphicsPath` 画圆角矩形填白底、`HighQualityBicubic` 等比缩放并把标志居中；③ 手写 ICO 容器（PNG 压缩条目，16/24/32/48/64/128/256），供 Windows 资源与 NSIS 使用；④ 同步导出演示站内嵌底图与 `base64.json`。图标与标志同源，改标志只需换 `logo.jpg` 并复跑脚本。

### 5.2 文书智能体技术要点

- 接入：OpenAI 兼容 `/chat/completions`，流式 + `tools`（function calling）+ 结构化 JSON（计划卡）；
- 引擎：`src/lib/agent.ts`——规划（模型 / 演示预设）、执行（模型驱动工具循环 ≤6 轮 / 确定性演示）、四角色提示词（规划 / 检索员 / 起草员 / 质检员）；
- 工具集：`laws_search / law_by_id / laws_country_preview / template_load / translate_text`（真实本地法库，可溯源）；
- 状态与记忆：`tasks / task_steps / task_artifacts / mem_vectors` 表；任务历史可载入续跑；跨任务向量 / 关键词召回。

### 5.3 检索演进（已落地）

`LIKE 全表扫描 → FTS5(trigram) + BM25（0.4.0 已实现，短词回退 LIKE）`；语义级"第二通道"列入远期（15 万条全量 embedding 不现实，建议关键词召回 + Top 结果喂模型）。

### 5.4 大模型环节流程细节（参赛创意描述口径：五环 + 旁路）

> 初赛要求创意描述含"使用大模型的环节流程细节"，以下为可直接引用/制作图解的文字版本。

**主链路（五环，数字员工一次端到端任务）**

1. **任务理解与规划**：LLM 结构化输出**计划卡**（步骤 JSON：3–8 步，含检索关键词与国家），前端可编辑、步骤可标记"需人工确认"；模型解析/规划失败时自动回退**预设流水线**并在界面明示"演示模式"（不静默降级）。
2. **工具决策与调用循环（function calling）**：模型在 `laws_search / law_by_id / laws_country_preview / template_load / translate_text` 间自主连续决策调用（≤6 轮），工具只返回**本地真实法条**并携带 `refs` 溯源；支持截断/超时/失败即停，关键步骤设人工闸门。
3. **起草**：起草员角色提示词约束——**只允许引用工具真实返回的法条**，输出固定结构文书正文（合同审查意见书 / 民事起诉状 / 质证意见）。
4. **质检（确定性引用自检）**：除模型复查外，执行器以**代码级规则**（非模型自查）解析正文中的"第X条 / 第X条のY / §N"等引用，逐一与本次工具真实返回比对，未覆盖引用在交付物与日志中**点名提示人工核实**、不计为有效引用。
5. **交付**：固定五段 Markdown（任务输入 / 执行过程 / 引用的法规条文（可溯源）/ 引用自检（确定性规则校验）/ 结论）→ 桌面一键导出 **.docx**（零依赖 OOXML）并记入首页"最近文书"、支持打开/定位；浏览器版下载 .md。

**旁路（赛事版口径）**：即时咨询不再单设 AI 问答栏——悬浮球面板"询问 AI"（本地法库检索增强）承担一问一答；需要交付成果时把材料直接交给小元走 1–5 闭环。

**降级矩阵（现场演示兜底）**

| 条件 | 行为 |
| --- | --- |
| 未配置模型 Key / 断网 | 演示模式：预设流水线 + 工具**真实执行**，全流程可跑 |
| 网关不支持 tools / json_object | 探测后回退预设流水线并明示"演示模式" |
| 模型规划解析失败 | 自动采用演示预设计划卡 |
| 浏览器预览（无 Tauri） | 数据降级 localStorage，工具环节以示例数据演示 |

### 5.5 记忆、长文本与赛道鼓励技术的对照（架构取舍，诚实口径）

- **记忆设计**：任务态持久化 `tasks / task_steps / task_artifacts`（中断可续跑、交付物归档）；跨任务长期记忆 `mem_vectors`（向量由前端调用 `/embeddings` 计算后入库，召回 LIMIT 500）。**如实说明**：长合同当前按 4k/6k 截断处理，完整的长文本按章节分块 + 要点抽取已列入 0.7.0（P1）。
- **检索增强（RAG）**：152,940 条/数百 MB 法库不做一次性全量 embedding（成本与时效不现实），采用"FTS5 关键词召回 → Top 结果喂模型"的务实 RAG；向量"第二通道"与命中重排列入远期。这是**数据规模下的工程取舍**，不是能力缺失。
- **多智能体对照**：当前为**单模型 + 四角色接力**（规划 → 检索员 → 起草员 → 质检员，各自独立系统提示词、执行链可视化）。状态机 + 角色解耦的架构已为 0.7.0 平滑升级到**真正多模型/多网关编排**预留空间；参赛口径如实表述为"单智能体内的多角色协作"，不夸大为多智能体系统。
- **多模态**：**0.7.0 起智能体材料输入已支持**——本地提取（离线可用）DOCX / PPTX / XLSX / TXT / MD / CSV（`office.rs`，手写最小 ZIP 读取 + flate2）；PDF / 图片需配置支持文件/视觉输入的模型（OpenAI 兼容 `image_url` / `file` content parts），转录文本一律带"模型解析、非原文"免责前缀，不进入原文引用口径。**音频不在范围**。法律文书交付仍以文本与 .docx 为主；悬浮球提供跨应用文本入口作为补充形态。

### 5.6 联邦配方进化技术方案概要（0.8.0 规划 · 方案稿，详见 [12-联邦配方进化方案.md](12-联邦配方进化方案.md)）

- **联邦对象（配方而非权重）**：计划卡模板 / 角色提示词参数 / 检索词典 / 质检阈值 / 记忆原型等 KB 级可审计编排资产；不做"大模型权重联邦"（模型走 API 无本地权重，云端亦不开放）；
- **本地侧**：复用现有任务日志（`tasks / task_steps / task_artifacts / mem_vectors`，无需新增采集）→ 特征提取（计划编辑 diff / 检索命中 / 审计通过率）→ 差分隐私 + K 匿名 → 产出 KB 级匿名"进化包"（默认 opt-in，可一键关闭）；
- **信号优势**：确定性引用自检（`auditCitations`）与计划卡人工编辑 diff = **零标注客观奖励信号**（代码规则产出，非模型自述、非用户问卷）；
- **聚合侧**：最小可行 = HTTP + SQLite；加权聚合（权重 = 样本量 × 审计通过率 × 新鲜度），只存聚合统计与配方版本、不存原文；
- **回程**：签名配方版本 → 本地 Shadow A/B → 指标改善后采纳，可一键回滚；
- **市场自适应**：聚合的 0 命中检索词 / 任务缺口驱动 0.9.0+ 产品路线（新法域、新任务模板、中文法库优先级）；
- **工程前置**：上行通道开通前将 Key 落盘/传输从混淆级升级为密码学加密 + TLS（现 `secret.ts` / `keycrypt.rs` 保持离线用途）。

## 九、商业模式与财务分析

本章基于本项目「AI＋涉外法律数据库服务平台」的产品战略与三年发展规划，给出商业模式画布、成本结构、收入来源、融资安排与财务预测，并对盈利能力、运营能力、偿债能力与税负作定量分析。以下金额单位均为万元，预测期为第一年至第三年；数据为团队基于现有规划与假设的测算，实际经营成果受市场环境、政策变化及执行情况影响。

> **口径说明**：本章按团队《财务分析与商业模式》材料编制，**客户细分与定价以本章为财务预测基准**；三章末《市场与商业可行性论证》为参赛"市场可行性"评分项的泛用性论证，两者视角不同（本章 = 商业化路径与三年财务口径，三章末 = 赛道评审口径），同列为规划依据。

### 9.1 商业模式

本产品是以涉外业务为核心的智能法律办公助手，覆盖高校学生公司/教授科研团队、出海企业、律师事务所，提供域外法律法规查询、智能文本分析、法律文书撰写与翻译服务。背靠西南政法大学域内外法律专家资源库，自主搭建全域法律数据库，提供学术型/实务型法律查明服务。以下按客户细分、价值主张、渠道通道、客户关系、核心资源、关键活动、关键伙伴等模块展开。

**客户细分**：核心客户分为三类：高校学生/教授科研团队、出海企业、律师事务所。前期为高校学生公司/科研团队提供学术型/实务型法律服务，实现客户从 0 到 1 的突破，积累品牌信誉并宣传法元办公助手；中期利用高校积攒的资源面向中小型企业提供公益服务与出海咨询服务，积累实务经验，逐步由公益服务转向付费、从小额咨询转向大额全链条服务；后期面向律所提供基于全域数据库的高度智能化办公助手。

**价值主张**：以涉外业务为核心的智能法律办公助手——高效、智能、低价。

- **高效**：悬浮球辅助阅读，选中内容即可生成翻译，自动关联相关国家、地区、法律与案例的基本信息，省去人工检索环节。
- **智能**：内部 AI 助手对文档进行整体分析，一键生成法律查明报告；文书模板支持导入不同业务类型并支持用户自行积累。
- **低价**：相比市场委托价格大幅降低，采用薄利多销策略，以规模换取市场覆盖。

**现金流口径**：销售收现按营业收入 × 95%（应收账款占 5%）测算；购买商品/接受劳务支付的现金按营业成本剔除固定资产折旧后的付现成本测算；支付的各项税费含增值税（6%）、附加税（实缴增值税的 12%）与企业所得税（25%）；支付其他与经营活动有关的现金为自媒体广告投放等付现费用（支付通道手续费已计入营业成本）。

**税费口径**：企业所得税按 25% 计提，小微企业可享税收优惠，实际税负可能更低；增值税按 6% 测算，如适用小规模纳税人征收率，税负更低。

**数据口径**：金额单位均为万元，小数按四舍五入保留；以上为团队基于现有规划与假设的财务预测，实际经营成果受市场环境、政策变化及执行情况影响。
