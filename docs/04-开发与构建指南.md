# 04 · 开发与构建指南

> **同步至 0.6.0（2026-09-06；0.6.0 为品牌切换「法元 · Faron」，功能面同 0.5.0）**。本文档说明「法元（Faron，工程名 legal-workbench）」的开发环境、常用命令、桌面版构建与已知注意事项。命令均在**项目根目录**（仓库根，即同时包含 `package.json`、`src-tauri/`、`floating-ball/` 的目录）执行。

## 1. 环境要求

| 依赖 | 版本 | 用途 | 备注 |
| --- | --- | --- | --- |
| Node.js | 20+ | 前端依赖与构建 | 开发机曾用 v24.x，见 `package.json` |
| npm | 随 Node.js | 依赖管理 | 仓库自带 `package-lock.json` |
| Rust | 1.77+（`rust-version` 声明） | Tauri 桌面壳编译 | 见 `src-tauri/Cargo.toml` |
| MSVC Build Tools / C++ 构建工具 | 最新 | Windows 下编译 Rust | 见下方说明 |

> 历史版本曾随仓库分发 `.install/` 工具链安装器，0.2.0 仓库瘦身时已移除（该目录已不在此仓库）。若首次在本机构建桌面版，请直接使用官方安装器：Rust 工具链用 `rustup-init`，Windows 编译环境用 Visual Studio Build Tools（勾选「使用 C++ 的桌面开发」工作负载），安装后确保 `cargo`、`rustc` 与 MSVC 链接器在 `PATH` 中。
>
> 桌面版开发还依赖 `floating-ball/` 的 Electron：仓库内 `floating-ball/package.json` 的 devDependencies 已含 `electron@^33`；如要联动悬浮球需先 `cd floating-ball && npm install`（或在首次 `npm run dev:all` / 顶栏唤起时由脚本 / 命令尝试定位并提示）。

## 2. 常用命令

```bash
# 安装依赖
npm install

# 浏览器预览（仅前端；数据降级到 localStorage 示例）
npm run dev            # http://localhost:1420

# 一键开发：拉起 Electron 悬浮球 + Vite（scripts/dev-with-ball.cjs）
npm run dev:all        # 自动清理占用 1420 的进程，先起悬浮球再启 Vite

# 类型检查 + 构建前端产物
npm run build          # tsc && vite build，输出 dist/

# 预览构建产物
npm run preview

# 桌面版开发（自动编译 Rust 并启动应用；启动时会自动拉起悬浮球）
npm run tauri dev

# 打包桌面安装程序（Windows：NSIS）
npm run tauri build
```

### 2.1 关键配置

- **`vite.config.ts`**：开发端口固定 `1420`（`strictPort: false`），`watch.ignored` 排除 `src-tauri/**`，`envPrefix` 同时支持 `VITE_` 与 `TAURI_`，`TAURI_DEBUG` 开启时保留 sourcemap 且不压缩；内置 `ballBridgePlugin`（轮询悬浮球桥接文件并推送给浏览器，暴露 `POST /__ball_cmd__` 控制端点写回控制文件）。
- **`src-tauri/tauri.conf.json`**：
  - `build.devUrl` = `http://localhost:1420`，`beforeDevCommand` = `npm run dev`。
  - `build.frontendDist` = `../dist`，`beforeBuildCommand` = `npm run build`。
  - 版本 `0.6.0`，产品标识 identifier `com.legalworkbench.app`（productName 为「法元」，窗口标题为「法元」；工程名 `legal-workbench`、主程序 exe 名与数据目录不变）。
  - **两个预声明窗口**：`main`（1200 × 760，最小 980 × 680，居中，标题「法元」）与 `float`（380 × 500，`alwaysOnTop`、默认隐藏、`skipTaskbar`，标题「AI 问答 · 悬浮」）。
  - bundle：`targets: ["nsis"]`；图标含 `icons/icon.ico` 等；resources 映射：`floating-ball/dist-060/win-unpacked → win-unpacked-0.6.0` 与 `preload/legal_preload.db → legal_preload.db`（0.6.0 已按此出包）。
- **`src-tauri/capabilities/default.json`**：`windows: ["main", "float"]`，权限 `core:default` + `notification:default`（待办系统通知）。

## 3. 两种运行模式

| 模式 | 启动方式 | 数据存储 | 适用场景 |
| --- | --- | --- | --- |
| 浏览器预览 | `npm run dev` | localStorage + 示例数据（`src/data/`） | 纯前端开发、UI 调试、无 Key 演示智能体全流程 |
| 桌面版 | `npm run tauri dev` | 本机 SQLite（`legal.db`）+ 系统通知 | 完整功能、联调 Rust 命令 |

前端通过 `src/lib/tauri.ts` 的 `isTauri()`（检测 `window.__TAURI_INTERNALS__`）自动区分环境，无需手动切换；悬浮球联动另区分「桌面（Rust 命令 / Tauri event）」与「浏览器（Vite 插件 / fetch）」两种桥（`src/lib/ball.ts`）。

## 4. 打包说明

```bash
npm run tauri build
```

流程：`beforeBuildCommand`（tsc + vite build）→ Cargo release 编译（`src-tauri/Cargo.toml` 已配置 `lto`、`codegen-units=1`、`opt-level="s"`、`strip`、`panic="abort"` 等体积优化）→ NSIS 打包。

- 产物位置：`src-tauri/target/release/bundle/nsis/法元_0.6.0_x64-setup.exe`（0.6.0 已出包至 `发布包/`，约 135.1 MB，内嵌法库预置库 + 悬浮球 `win-unpacked-0.6.0`；0.5.0 历史包为 `律衡_0.5.0_x64-setup.exe`）。
- `src-tauri/target/` 与 `dist/` 为构建产物，`.gitignore` 已排除，不进版本库。
- 升级安装注意：悬浮球装入版本化子目录（`win-unpacked-<版本>`），升级时写入新目录、不与旧进程抢文件；安装 / 升级前建议先退出正在运行的法元（旧版：律政工作台 / 律衡；悬浮球从托盘一并退出）。

## 5. 启动脚本说明（浏览器预览）

项目根目录提供两个启动脚本（Vite + 浏览器预览模式，非 Tauri 桌面版）：

- `启动律政工作台.bat`：设置 Node PATH 后 `cd` 到项目目录，先打开 `http://localhost:1420` 再 `npm run dev`。
- `启动律政工作台.vbs`：静默启动 Vite，延迟 3 秒打开浏览器。

> 这两个脚本目前**硬编码了原作者机器的路径**（Node 目录 `E:\node-v24.19.0-win-x64\...` 与项目目录 `E:\DEMO`），与本机实际位置不一致，直接运行会失败；如要使用请按本机实际路径修改（或将 Node 加入系统 PATH 后仅保留 `npm run dev`）。

## 7. 待办事项与已知缺口

当前功能面已基本齐全（数据导入、桌面弹窗提醒、最近文书等历史缺口均已实现）。剩余真实缺口详见 [05-优化路线图.md](05-优化路线图.md)，与本项目开发相关的最重要几条：

1. **自动备份无定时调度**：`backup.auto` / `backup.interval_days` 仅持久化配置，未实现后台调度执行。
2. **无自动化测试 / lint / CI**：`package.json` 无 `test` / `lint` 脚本（`build` 内含 `tsc` 类型检查）；Rust 侧无 `#[cfg(test)]`。
3. **数据库迁移无版本号**：`migrate()` 靠幂等 DDL + 列存在性检查，无 schema 版本表。
4. **docx 导出为 Markdown 子集**：`docx.rs` 支持标题 / 列表 / 引用 / 代码块 / 加粗 / 行内代码，不支持表格、批注、审阅痕迹等高级版式。
5. **悬浮球相关**：开发联动需 `floating-ball` 就绪（`npm install` 或 `npm run dist`）；找不到 Electron 时 `dev:all` 与命令会提示而非静默成功。

## 8. 常见问题

**Q：`npm run dev` 后浏览器打开页面但没有数据 / 按钮不可用？**
浏览器预览模式数据来自 localStorage 示例数据（首次访问自动注入），法规 / 模板 / 待办均可体验；备份还原、Excel 导入等标注「仅桌面版可用」的功能需桌面版；AI 问答 / 智能体未配置模型时进入演示模式（智能体工具步骤仍真实执行，可下载 .md 交付物）。

**Q：`npm run tauri dev` 报 Rust / MSVC 错误？**
确认已安装 Rust（`rustc --version` ≥ 1.77）与 Visual Studio Build Tools（含 C++ 工作负载）。本仓库已不随带安装器，请使用官方安装器补齐。

**Q：桌面版里悬浮球点不开且无报错？**
0.4.0 起启动失败不再静默：先看 Rust 控制台 `[ball]` 日志；`ball_show` 等命令失败会在前端弹窗显示原因（`src/lib/ball.ts`）。常见原因是找不到悬浮球（可设环境变量 `FLOATING_BALL_DIR`，或把 `悬浮球助手*.exe` 便携版 / `win-unpacked-<版本>` 放到主程序同目录）。

**Q：修改前端代码后桌面版不生效？**
Tauri 开发模式使用 `devUrl`（Vite 热更新），正常应即时生效；若修改了 `src-tauri/` 下的 Rust 代码，需重启 `npm run tauri dev` 重新编译。前端端口被占用时可先清理占用 1420 的进程（`dev:all` 会自动做）。

**Q：打包时法库 / 悬浮球没进安装包？**
检查 `tauri.conf.json` 的 `bundle.resources` 映射（`preload/legal_preload.db` 与 `floating-ball/dist/win-unpacked`）以及 `floating-ball` 是否已执行过 `npm run dist`（需先生成 `win-unpacked` 产物，且文件未被占用）。
