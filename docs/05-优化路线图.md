# 05 · 优化路线图

本文档汇总律政工作台（v0.1.0）的后续优化方向，按优先级 P0 → P3 组织，每条建议均对应到源码位置，可作为版本迭代的任务清单。

优先级说明：

- **P0**：把占位变为可用，是「演示版 → 可日常使用」的关键。
- **P1**：架构与技术债，影响长期维护与数据规模。
- **P2**：体验优化。
- **P3**：工程化与发布配套。

## P0 · 功能补全

| 缺口 | 源码位置 | 建议方案 |
| --- | --- | --- |
| Excel 数据导入未实现 | `src-tauri/src/lib.rs` 的 `import_data`（仅返回提示，标注 `TODO`） | 用 Rust 的 `calamine` 解析 Excel，按字段映射写入 `laws` / `templates` 表；前端「数据导入」页实现「选择文件 → 字段映射预览 → 确认导入」三步 |

## P1 · 架构与技术债

1. **全局数据不同步**：`useTodos` 在 `Sidebar`、`Home`、`Todo` 各自独立拉取，新建待办后侧栏 badge 不会实时更新。建议引入轻量全局状态（Zustand 或 Context），或给数据层增加变更事件，一处修改全界面刷新。
2. **SQLite 全局锁串行化**：`src-tauri/src/db.rs` 用 `Mutex<Connection>` 包裹唯一连接，所有命令排队访问。数据量增长后会卡顿，可拆分为读/写双连接或引入连接池（如 `r2d2`），至少将耗时查询移出锁。
3. **设置读写 IPC 过多**：`src/hooks/useSettings.ts` 加载时逐键调用 `settings_get`（约 10 次串行）。建议合并为 `settings_get_all` / `settings_set_batch` 批量命令。
4. **命令冗余与类型隐患**：`todos_update` 与 `todos_save` 功能重叠，建议合并；`todos_update` 中以 `id.to_string()`（TEXT）绑定 INTEGER 列，SQLite 亲和性下可工作但属于隐患，应直接传 `i64`。
5. **翻译配置误用 AI 模型**：`src/views/Translate.tsx` 的付费翻译使用 `s.ai.model`，建议增加独立的翻译模型配置，避免两者互相影响。
6. **工程规范缺失**：
   - 补 ESLint + Prettier（当前 `package.json` 无 lint 脚本）。
   - 引入测试：前端用 Vitest 覆盖 `searchLaws`、翻译、`chatStream` 解析等纯函数；Rust 侧为 `db.rs` 补单元测试。
   - 数据库迁移加版本号（当前 `CREATE TABLE IF NOT EXISTS` 无法支撑后续改表，建议引入版本化迁移）。

## P2 · 体验优化

- **AI 助手**（`src/views/Assistant.tsx`、`src/lib/ai.ts`）：
  - 会话持久化到 SQLite，刷新不丢。
  - 支持中止生成（AbortController）。
  - Markdown 渲染与消息复制按钮。
  - 历史消息滑动窗口（当前每次请求携带全部历史，越长越慢越贵）。
- **悬浮窗**：记忆位置与尺寸（持久化窗口状态或存 settings）、系统托盘、全局快捷键唤起。
- **法规库**：大数据量分页 / 增量加载，搜索结果关键词高亮，导入后按篇名树形浏览。
- **模板库**：导出 Word / PDF，把 `____` 下划线占位改为表单化填充后生成文书。
- **待办**：真正的定时提醒、日历视图。
- **翻译**：历史记录、术语表、长文自动分段（免费接口存在长度限制，源码已提示「字数过多」场景）。

## P3 · 工程化与发布

1. **完成 release 打包**：当前 `src-tauri/target/` 仅有 debug 构建，尚无安装包。执行 `npm run tauri build` 产出安装程序，并做安装 / 卸载冒烟测试。
2. **安全加固**：
   - `src-tauri/tauri.conf.json` 中 `csp: null`，建议开启 CSP。
   - API Key 明文存 SQLite（`settings` 表），建议改存系统钥匙串（Windows Credential Manager），至少在设置页提示风险。
3. **发布配套**：接入 `tauri-plugin-updater`（自动更新）、`tauri-plugin-log`（日志）、CI（GitHub Actions：lint + test + 构建）。
4. **仓库卫生**：`src-tauri/target/`（约 1.5 GB）与 `node_modules/` 不进版本库（`.gitignore` 已排除）；`.install/` 的两个工具链安装器移出项目目录；`启动律政工作台.bat` / `.vbs` 的硬编码路径参数化。
5. **备份可靠性**：WAL 模式下先 `checkpoint` 再复制数据库文件，备份后做完整性校验（当前为文件级裸复制，见 `backup_now`）。

## 建议里程碑

| 里程碑 | 范围 | 达成标志 |
| --- | --- | --- |
| A · 可用版 | P0 全部 + release 打包 | 从演示变为可日常使用的工具 |
| B · 稳定版 | P1 全局状态、数据库并发、测试与 lint | 地基牢固，可积累真实用户数据 |
| C · 好用的产品 | P2 体验项 + P3 发布配套 | 具备发布与持续迭代能力 |
