# 05 · 优化路线图

> **同步至 0.5.0（2026-09-06）**。本文档为**真实剩余缺口清单**：0.1.0 ~ 0.4.1 之间的功能路线（Excel 导入、桌面弹窗提醒、最近文书、FTS5 检索、内置日美法库、文书智能体、确定性引用自检、悬浮球一体化等）均已兑现，不再列入；以下仅保留「对照当前源码仍未完成」的项目，按 P0 → P3 组织，每条均对应到源码位置，可作为后续版本迭代的任务清单。

优先级说明（相对 0.4.1 的剩余状态重新定义）：

- **P0**：数据安全底线——影响「本地单机」承诺的可信度。
- **P1**：架构与技术债——影响长期维护与数据规模。
- **P2**：体验与智能化——产品质感的增量改进。
- **P3**：工程化与发布配套。

> 涉及性能 / 真机体验的条目，本仓库文档不写未经实测的数字；如需评审数据，请以 [07-真机验收清单.md](07-真机验收清单.md) 的真机验收为准。

## P0 · 数据安全（本地单机承诺的短板）

| 缺口 | 源码位置 | 建议方案 |
| --- | --- | --- |
| 自动备份只有配置、没有定时调度 | `settings` 表 `backup.auto` / `backup.interval_days` / `backup.target_dir` 仅持久化（`src/hooks/useSettings.ts`）；`backup_now` 只能手动触发（`src-tauri/src/lib.rs`） | 仿照待办通知轮询（每 30s 的 `check_todo_notifications` 后台线程），新增按天周期检查的调度线程，到点调用现有 `backup_now` 逻辑；或接入系统任务 / 调度插件 |
| 备份 / 还原为文件级裸复制，无 WAL checkpoint 与完整性校验 | `backup_now` / `restore`（`lib.rs`）直接 `fs::copy` | 备份前对连接执行 `PRAGMA wal_checkpoint(FULL)`（或 `VACUUM INTO`），备份后做打开校验 / 行数核对；还原前同样备份现状 |

## P1 · 架构与技术债

1. **全局数据不同步**：`useTodos` / `useDocuments` 等在各组件（`Sidebar`、`Home`、`Todo`、`Agent`）中各自独立拉取与持有一份状态，无全局 Store / 变更事件；新建 / 删除后其它界面不会实时联动。建议引入轻量全局状态（Context / Zustand），或给数据层增加变更通知。
2. **SQLite 全局锁串行化**：`src-tauri/src/db.rs` 用唯一 `Mutex<Connection>`（`DbState`）包裹，所有命令排队访问，任何慢查询会阻塞全部命令。建议拆读 / 写连接或引入连接池，至少把耗时查询（如 `laws_search` 的 FTS / LIKE）移出共享锁路径。
3. **设置读写 IPC 过多**：`src/hooks/useSettings.ts` 载入时逐键串行调用 `settings_get`（约 10 次）。建议合并为 `settings_get_all` / 批量写命令。
4. **命令冗余与类型隐患**：`todos_update`（仅 done / title）与 `todos_save`（全字段）功能重叠；`todos_update` 里 `title` 更新以 `id.to_string()`（TEXT）绑定 INTEGER 列，SQLite 亲和性下可工作但属隐患，应直接传 `i64`（`lib.rs`）。
5. **数据库迁移无版本号**：`db.rs::migrate()` 靠 `CREATE TABLE IF NOT EXISTS` + `ensure_column`（`PRAGMA table_info` 查列）幂等演进，没有 schema 版本表；未来复杂改表（重命名列 / 数据搬运）难以表达。建议引入版本化迁移（记录 `PRAGMA user_version` 或 migrations 表）。
6. **智能体超长文本无自动分块**：`agent.ts` 对任务材料直接 `slice(4000 / 6000)` 截断（规划、推理、工具循环均截断输入），超长合同 / 长证据材料无法完整覆盖。建议按条 / 按章节分段 + 逐段要点抽取 + 汇总的流水线，再进入起草步骤。

## P2 · 体验与智能化

- **语义检索需先关键词召回**：法规库约 15 万条 / 数百 MB，不做全量 embedding（0.3.2 曾下线「向量检索」入口）；智能体记忆召回在未配置模型时也退化为关键词包含匹配（`agent.ts::recallMemory`）。可选方向：对**关键词召回结果**切片做重排 / RAG，而非全库向量化。
- **docx 高级版式未做**：`src-tauri/src/docx.rs` 零依赖 OOXML 仅支持 Markdown 常用子集（`# ~ ####` 标题、列表、引用、代码块、加粗、行内代码），无表格、批注、审阅痕迹、页眉页脚、样式化标题 / 页码。文书类交付物若要达到「直接提交」水准需扩展（或引入 docx 模板引擎）。
- **内置中文法库缺失**：预置库仅日美（日本 95,897 + 美国 57,037 条），中国仅 6 条《民法典》示例（`db.rs::seed_laws_if_empty`）；中文真实检索依赖用户 Excel 导入。建议按文档（07 真机验收清单中的中文法库接入方案）补充清洗后的公开中文法源与装载/校验流程。
- **法规查询体验**：命中关键词高亮、按篇名树形浏览 / 展开收起、结果分页（当前命中上限 500 条只提示「细化关键词」）。
- **AI 问答历史滑动窗口**：每次请求携带当前会话全部历史（`Assistant.tsx`），长会话越来越慢越贵；可做近 N 轮 + 摘要压缩。
- **翻译**：免费接口有长度限制（源码在超长/不支持语种时抛错），长文自动分段未实现；翻译历史、术语表未做。
- **Tauri 置顶悬浮窗体验**：`float` 窗口为固定 380 × 500 预声明，无托盘图标、无全局快捷键、无位置/尺寸记忆（区别于 Electron 悬浮球，后者已有皮肤/托盘能力）。
- **模板库**：`____` 待填项表单化填充未做；模板导出 .docx / PDF 未做。
- **Excel 导入字段映射 UI**：`import_excel` 目前按固定列名（中英文表头）映射，无拖拽选择文件、无列映射预览；重复导入不去重。
- **待办**：无日历视图；提醒仅限到期前提醒，无重复性（每日/每周）待办。

## P3 · 工程化与发布配套

1. **自动化测试 / lint / CI 缺失**：`package.json` 无 `test` / `lint` 脚本（仅 `build` 内 `tsc` 类型检查），Rust 侧无 `#[cfg(test)]`，无 GitHub Actions。建议：Vitest 覆盖 `searchLaws` / 翻译 / `chatStreamOnce` / `agent.ts` 的 `extractCitationTokens` / `auditCitations` 等纯函数；Rust 为 `db.rs` / `keycrypt.rs` / `docx.rs` 补单元测试；补 ESLint + Prettier；CI 跑 lint + test + 构建。
2. **发布配套**：未接 `tauri-plugin-updater`（自动更新）、`tauri-plugin-log`（日志）；版本升级与安装包发布流程为手动。
3. **安全加固**：
   - `tauri.conf.json` 中 `security.csp` 为 `null`，建议按需开启 CSP。
   - API Key 为 XOR+hex **混淆**（`keycrypt.rs`，`enc:` 前缀 + 启动幂等迁移），目标只是避免明文裸露可被直接读取 / grep；属客户端混淆而非强加密。更高安全诉求可接入系统凭据管理器（Windows Credential Manager）；悬浮球（Electron）侧同样为混淆存储。
   - `open_file` 白名单扩展名已限定（docx/doc/md/txt/xlsx/xls/pdf/html/htm/csv），若后续放开请同步收紧。
4. **仓库卫生与发布脚本**：`启动律政工作台.bat` / `.vbs` 硬编码原作者路径（`E:\node-v24.19.0...`、`E:\DEMO`），与本机实际布局不一致，建议参数化或改为读取 Node 环境变量。
