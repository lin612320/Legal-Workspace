## 〇、评委视角速答（三连问）

- **Q：模型走 API，权重根本不在本地，你联邦了什么？**
  A：我们不联邦大模型权重（也不需要）。联邦的是"小元会不会干活"的**可训练编排资产**——计划卡配方、检索词典、质检阈值、记忆原型。它们体积 KB 级、可审计、可签名下发、可一键回滚；而大模型权重既不在本地，云端 API 也不会把权重交给我们聚合。联邦对象降维后，机制才真正成立。
- **Q：凭什么说"不涉及用户隐私"？**
  A：三个词：**数据最小化**（上云只有白名单统计与配方向量，原文/密钥/文书零上云）+ **差分隐私**（本地加噪，单条不可还原）+ **最小匿名集合**（不足 K 人不聚合，TLS + 签名防篡改）。默认关闭，关掉完全不影响离线核心链路。可现场抓包验证载荷里没有案情文本。
- **Q：用户量不够，怎么证明可行？**
  A：协议诚实仿真——本地跑 3–5 个"律所用户"（不同任务类型 / 法域 / 编辑习惯），各自产出匿名进化包，同一台机器执行**真实聚合代码**，展示收敛曲线与可量化提升；进阶可 2–3 台真机局域网演示真实传输。真实规模验证放在**律所私有化联邦域**试点（企业版第三档商业模式，几台机器即可跑通）。

## 一、动机与目标

### 1.1 想解决的问题

法元 0.4.0–0.6.0 已交付的智能体「小元」是**静态智能体**：每条流水线、每套提示词、每个检索词典对所有用户一视同仁；任务经验只沉淀在单个用户本地的 `mem_vectors`，**跨用户、跨所、跨市场是隔离的**。由此产生四个真实缺口：

1. **不随用户变好**：张三长期做涉日合资合同、李四做赴美出口管制，两人会各自手工把计划卡改成不同形态（`Agent.tsx::applyEditedPlan`），但这些"更好的做法"互相看不见，也不会回馈给默认流水线；
2. **不随市场变好**：当大量用户检索同一类词而本地库 0 命中（如某部中文新法、某类英文监管条款），产品侧看不到这个"需求缺口"，路线图只能靠拍脑袋排期；
3. **经验不可迁移**：本地记忆只服务本机召回，新装机的用户从小元 0 经验起步；
4. **云上冷启动的悖论**：若反过来把用户任务原文上云训练，又与法元"数据不出本机"的核心卖点直接冲突（docs/08 §五竞品页、§九 Q&A 已固化该口径）。

### 1.2 目标（方案稿口径）

借鉴联邦学习（Federated Learning）"**数据不动、模型动**"的范式，为法元设计一条 **"本地只出增量、云端加权聚合、回传更好配方"** 的自进化闭环：

- 本地侧：在既有任务日志上做**特征提取与（可选的）轻量本地训练**，产出 KB 级**匿名进化包**，默认 opt-in、可随时关闭；
- 云端侧：只存**聚合统计与配方版本**（不存原文），按"样本量 × 质检质量 × 新鲜度"**加权聚合**（FedAvg 思路）；
- 回程侧：**签名配方版本**下发 → 本地 A/B 试运行 → 指标改善后采纳，用户可一键回滚；
- 市场侧：聚合的"0 命中检索词 / 任务类型缺口 / 失败模式"作为**产品路线图的数据输入**（新法域、新任务模板、中文法库优先级），让"智能体随用户需求与市场自我优化"落在**产品层真实闭环**，而不是玄学级"模型自进化"。

### 1.3 非目标与红线（方案稿即约束）

- **不做**：任何形式的用户原文 / 案情 / 文书 / 密钥 / API Key 上云；
- **不做**：宣称"联邦/聚合大模型权重"（现有架构无本地权重，见 §3.3）；
- **不做**：默认开启上传（默认关，与"单机可用"定位一致；核心链路离线不受影响）；
- **不做**：把本方案写进 0.6.0 赛事版"已实现"清单——它是路线图与加分素材，参赛主叙事维持 docs/08 口径不动。

## 二、核心概念：为什么联邦"配方"而不是"权重"

### 2.1 术语表

| 术语 | 英文 | 定义 |
| --- | --- | --- |
| 配方 | Recipe | 围绕大模型、可版本化下发的一组**编排资产**：计划卡模板 / 角色提示词参数 / 检索词典 / 质检阈值 / 记忆原型等 |
| 进化包 | Evolution Package | 本地产生的 KB 级匿名增量（统计 + 配方向量），是上云的唯一载荷 |
| 配方版本 | Recipe Manifest | 云端聚合产物，带版本号与签名，本地校验后 A/B 采纳 |
| 确定性自检信号 | Audit Signal | `agent.ts::auditCitations` 输出的代码级质检结果，作为客观奖励信号 |
| 联邦域 | Federation Domain | 聚合边界：跨所匿名云域（opt-in）或律所/企业内网私有域 |

### 2.2 三种联邦对象对比

| 联邦对象 | 本地有无 | 可训练性 | 上云安全 | 可下发 | 结论 |
| --- | --- | --- | --- | --- | --- |
| **大模型权重**（LLM Weights） | 无（智能走云端 API，`ai.ts::chatStreamOnce`） | 无 | 差（梯度可被还原训练数据） | 无（厂商不给） | ✗ 不可行 |
| **本地小模型**（行为/排序模型） | 可造（特征来自任务日志） | ✅ 可（GBDT/逻辑回归/LoRA 级） | 中（需差分隐私） | ✅ | △ 远期选项（见 §3.4） |
| **编排配方**（Recipe） | ✅ 现成（计划卡 / 词典 / 阈值结构已存在） | ✅ 统计 + 配方向量 | 好（白名单 + 聚合统计） | ✅ 签名 + A/B | ✅ **本方案对象** |

### 2.3 法元选"配方"的三个硬理由

1. **架构现实**：智能体是"OpenAI 兼容 API + 本地工具循环 + 确定性质检"的编排架构（`agent.ts` / `tools.ts`），**真正能改进且属于我们的，正是编排层**——提示词配方、计划卡模板、检索词典、质检阈值。这一层改好了，交付质量直接提升，且与模型厂商无关。
2. **可审计安全**：配方是 KB 级结构化数据，能签名、能 diff、能回滚；权重聚合则带来群体性幻觉与投毒风险——法律场景对"编法条"零容忍（docs/06 §十三 引用幻觉已是最高风险），配方层天然规避。
3. **可演示可信**：聚合过程可用真实代码在评审现场复现（收敛曲线 + 提升指标），延续法元"硬校验而非自述"的一贯叙事（docs/08 §十一-A 的"埋雷话术"同构）。

## 三、可行性评估（基于现有代码）

### 3.1 结论总表

| 评估项 | 结论 | 依据 |
| --- | --- | --- |
| 本地信号可得性 | ✅ 高 | 任务全量落库 `tasks / task_steps / task_artifacts`（docs/03 §2.7），质检结论在 `result_ref`，无需新增采集 |
| 客观奖励信号 | ✅ 高（且独特） | 确定性引用自检（`auditCitations`）+ 计划卡人工编辑 diff + 人工闸门，均零标注 |
| 上云载荷最小化 | ✅ 高 | 白名单统计 + 配方向量，可做到 KB 级 |
| 聚合端可实现 | ✅ 高 | 最小可行 = HTTP 服务 + SQLite，无需训练集群 |
| 下发与回滚 | ✅ 高 | 签名 manifest + 本地 A/B（shadow mode），现有 settings 机制可承载开关 |
| 隐私可辩护 | ✅ 中（需差分隐私） | 依赖工程纪律；现有 Key 混淆需升级为真加密后再开放上行 |
| 权重级联邦 | ✗ 不可行 | 模型不在本地；API 厂商不开放权重 |
| 评审风险 | 中 | "联邦=偷隐私"认知风险，需话术与抓包实证对冲（§6、§10） |

### 3.2 现有架构免费提供的"信号资产"（对照表）

| 现有实现 | 位置 | 免费信号 |
| --- | --- | --- |
| 任务状态机（含计划卡 `plan_json`、执行状态、结果摘要） | 表 `tasks / task_steps`；`agent.ts::planTask` | 计划卡结构、步骤成败、每步耗时 |
| 计划卡人工编辑 | `Agent.tsx::applyEditedPlan`（用户改后全量替换步骤） | **用户对默认计划的增删改 diff = 偏好标注** |
| 确定性引用自检 | `agent.ts::extractCitationTokens / auditCitations / auditReport`；`task_steps.result_ref` | **引用覆盖数 / 未点名清单 = 代码级质量标签**（非模型自述、非用户问卷） |
| 工具真实调用日志 | `tools.ts`（`laws_search / law_by_id / template_load / translate_text`）+ 执行日志 | 检索词命中率、0 命中词、按国家/领域分布 |
| 跨任务记忆 | 表 `mem_vectors`（向量由 `/embeddings` 计算回存，docs/03 §2.8）；`agent.ts::recallMemory` | 记忆向量可聚类出"经验原型" |
| 人工确认闸门 | `task_steps.need_confirm` | 用户放行/中断的位置 = 风险敏感点标注 |
| 设置持久化 | `useSettings.ts`（`settings` 表，secret 走 `enc:` 混淆） | 已有加密入口，可直接承载"进化开关/域地址"配置 |

> 关键点：**通用联邦学习最缺的是标签，法元的任务日志自带标签**——审计信号是代码规则算出来的，不是用户填问卷。这是本方案区别于"云端收集反馈再 RLHF"的最大差异点，也是答辩最容易讲清的一点。

### 3.3 关键约束（必须先承认的硬事实）

1. **模型权重不在本地**：全部智能走用户自配 OpenAI 兼容 API（`ai.ts` 默认 `gpt-4o-mini`）；悬浮球（`floating-ball/src/ai.js`）同理。故**权重级联邦在本架构下不成立**。
2. **"不涉及隐私"是危险表述**：即使只传统计与配方向量，也可能被**成员推断 / 属性推断**攻击；法律文书还叠加律师-客户特权。可辩护的口径必须上**差分隐私 + 最小匿名集合**（见 §6）。
3. **现有 Key 落盘是混淆不是加密**：`src/lib/secret.ts` / `src-tauri/src/keycrypt.rs` 为 XOR+hex（README 已如实写"混淆"）。任何上行通道开通前，传输与身份认证必须升级为真加密（TLS + 证书），否则与隐私叙事自相矛盾。
4. **噪声与质量权衡**：差分隐私噪声会稀释小样本聚合质量——对策是**配方层只聚合高频统计**（按任务类型/法域分桶），低样本桶宁可不聚合（K 匿名下限）。

### 3.4 参照系：业界联邦学习的适用条件对照

| 条件 | 业界典型案例（Gboard / Apple 键盘等） | 法元 · FRE |
| --- | --- | --- |
| 模型规模 | 小模型、单任务 | 不做模型权重，只做编排配方（规模更小） |
| 训练数据 | 打字序列 | 任务日志（本身已在本地结构化） |
| 奖励/标签 | 弱（用户是否使用候选） | **强（确定性自检 + 计划编辑 diff）** |
| 数据敏感度 | 中 | 高（法律），但**原文不上云**，风险面显著小于业界上传梯度 |
| 部署形态 | 移动端长连接 | 桌面 + 可选企业联邦域 |

结论：业界能做权重联邦的前提（模型在本地、单一封闭任务）法元不具备；但法元具备业界羡慕的**强标签**。把联邦对象换到配方层后，本方案比"通用 FL"更轻、更安全、更好演示。

## 四、总体架构与数据流

### 4.1 本地侧（离线优先，五模块）

```
用户用「小元」做任务
  └→ ① 信号采集器（读本地 SQLite：tasks/task_steps/task_artifacts/mem_vectors，
        不新增业务采集点）
  └→ ② 特征提取（计划编辑 diff 统计 / 检索词命中 / 审计通过率 / 步骤轮数）
  └→ ③ 轻量本地训练（可选 v2：聚类记忆原型 / 词典增量，OpenAI 兼容接口只用于
        离线向量的本地降维，不上行）
  └→ ④ 隐私处理（字段白名单 → 差分隐私加噪 → ≥K 匿名集合判定）
  └→ ⑤ 进化包出口（KB 级 JSON + 版本号 → TLS 上行；默认 opt-in，可一键关闭/清除）
```

与现有模块映射：

| 新模块 | 落地参考（现有代码） |
| --- | --- |
| 信号采集器 | 复用 `db.rs` 的 `task_get / task_steps_save` 数据；浏览器预览降级 localStorage（同 `mem_vectors` 现有降级策略） |
| 特征提取 | 新增纯函数模块（仿 `agent.ts` 中 `auditCitations` 的纯函数风格，可单测） |
| 进化包出口 | 新增 Rust 命令（仿 `backup_now` 的上行出口 + 开关），`settings` 表存域地址/开关（secret 走升级后的加密） |

### 4.2 聚合侧（最小可行 = HTTP + SQLite，无训练集群）

```
聚合器（云端/企业域）
  接收进化包 → 校验签名与白名单 schema → 丢弃 <K 匿名桶
  → 加权聚合（权重 = 样本量 × 审计通过率 × 新鲜度衰减）
  → 产出「配方版本 manifest」{ plan_templates_update, lexicon_update,
       prompt_param_update, qa_threshold_update, memory_prototypes }
  → 签名 → 供本地拉取
```

- 一期不需要账号体系与用户画像：按「任务类型 × 法域 × 语言」匿名分桶聚合即可；
- 存储上限明确：只存聚合统计与配方版本（**不存原文、不存进化包原文**），体积天然受限，也就没有"云账单爆炸"问题（docs/08 §六 商业模式的成本口径不受冲击）。

### 4.3 下发与回滚

1. 本地按版本号拉取 manifest → 校验签名与 schema；
2. **Shadow 试运行**：未来 N 个任务并行评估"新配方 vs 现配方"（仅在本地，不出网）；
3. 指标改善（计划卡编辑率↓ / 审计通过率↑ / 0 命中↓）则**采纳**并写 CHANGELOG 式本地记录；
4. 任何一步异常即回滚到上一配方版本，用户可在设置页一键停用进化并清除已下载配方。

### 4.4 与现有"版本化/降级"哲学的兼容

法元已有成熟的"双环境降级"（桌面 SQLite / 浏览器 localStorage，`tauri.ts::isTauri`）与"演示模式"（`agent.ts::DEMO_REASON_PREFIX`）。FRE 采用同一哲学：**无网络/未 opt-in/聚合端不可达时，一切照常离线运行**；进化只是"可选的额外收益"，不是依赖。

## 五、联邦对象与信号定义（版本 1 实现口径）

### 5.1 进化包字段示例（白名单，全部为聚合统计与配方向量）

```jsonc
{
  "schema": "fre.evolution-package/v1",
  "client": "0.8.0",
  "bucket": { "task_kind": "review", "country": "JP", "lang": "zh" },
  "sample_n": 42,                              // 本桶样本量（≥K 才可上行）
  "plan_edit": {                               // 计划卡人工编辑 diff 统计
    "default_steps_removed": {"条款拆解": 3, "风险排序": 1},
    "added_tool_sequence": [["laws_search", "law_by_id"], 7]
  },
  "lexicon": {                                 // 检索词典增量
    "zero_hit_keywords": {"遺留分": 4, "出口管制条例": 2},   // 已是 ≥K 桶
    "good_keywords": {"契約": 31, "trademark": 18}
  },
  "quality": {                                 // 确定性自检结果聚合（代码规则产出）
    "audit_pass_ratio": 0.94,
    "unmatched_tokens": {"第9999条": 2}
  },
  "memory_prototype": [0.012, -0.031, ...],    // 记忆聚类原型向量（DP 加噪后）
  "dp": { "mechanism": "gaussian", "epsilon": 3.0 }
}
```

> 以上为**示例字段**（数值为占位），最终 schema 在 P0 阶段按 docs/03 的表结构定稿并做差分隐私敏感性分析。

### 5.2 奖励信号设计（零标注，全部来自现有日志）

| 信号 | 来源 | 含义 |
| --- | --- | --- |
| 计划卡人工编辑 diff | `Agent.tsx::applyEditedPlan` 前后的 steps 对比 | 用户对默认工作流的隐式偏好 |
| 引用审计通过率 | `auditCitations(evidence, task.refs)` | 交付质量的客观度量（未点名/点名） |
| 检索命中率与 0 命中词 | `laws_search` 执行日志 | 词典缺口与数据缺口 |
| 闸门放行/中断 | `task_steps.need_confirm` 状态流 | 风险敏感点 |
| 任务完成度与导出 | `tasks.status` + `task_artifacts` 落盘 | 端到端成功与否 |

### 5.3 加权聚合与收敛度量

- 聚合权重：`w_i = sample_n_i × audit_pass_i × exp(-λ·age_i)`（质量加权而非纯数量加权，防止"低质高频"桶主导）；
- 收敛度量（全部可量化、可进演示曲线）：

| 指标 | 方向 | 来源 |
| --- | --- | --- |
| 计划卡平均人工编辑次数 | ↓ | 步骤 diff 计数 |
| 引用自检通过率 | ↑ | `auditCitations` |
| 检索 0 命中率 | ↓ | `laws_search` 日志 |
| 每任务平均工具轮数 / token 用量 | ↓ | 执行日志 |
| 新配方采纳后回滚率 | ↓ | manifest 版本流 |

### 5.4 A/B 采纳与回滚

- Shadow 模式：新配方与现配方并行评估 N 个任务（默认 N=10，可配）；
- 采纳条件：多数指标同向改善且无单指标显著回退；
- 回滚：保留最近 2 个配方版本，异常即回退；用户设置页可查看"本机进化日志"（版本 / 时间 / 指标变化，本地留存、可删）。

## 六、隐私、安全与合规（答辩口径）

### 6.1 三层机制（正式表述，替代"不涉及隐私"）

1. **数据最小化**：上云仅 §5.1 白名单统计与配方向量，原文 / 密钥 / 文书零上云——现场可抓包验证载荷；
2. **差分隐私**：本地加噪（Gaussian / Laplace），单条记录不可还原，`epsilon` 作为公开参数可审计；
3. **最小匿名集合 + 安全通道**：低于 K（如 20）样本的桶不上行；TLS + 签名防篡改与伪造。

### 6.2 工程前置（开放上行前的硬门槛）

- Key 落盘与传输从 XOR+hex **混淆**升级为密码学加密 / TLS 证书（现 `secret.ts` / `keycrypt.rs` 保持离线用途，上行链路另立真加密通道）；
- 进化包出口只读、白名单校验、**不发敏感字段**（禁止 `context / content / title_zh / result 原文` 类字段出网）——用 schema 强制而非自觉；
- 提供"完全本地模式"：永不创建上行任务（默认），核心链路离线可用不受影响。

### 6.3 合规要点

- 个人数据处理遵循最小必要与明示同意（opt-in）；聚合端以统计为主，降低《个人信息保护法》下"个人信息处理者"的合规面；
- **企业联邦域是合规最干净的形态**：律所/涉外集团内网自建聚合域，数据全程不出所内——既保律师-客户特权，又让"小元越用越懂本所业务"成为私有化授权（docs/08 §六 第三档商业模式）的卖点；
- 聚合产物若对外展示（如"进化日志"公开页），只展示聚合指标与配方版本，不展示任何单用户/单所明细。

### 6.4 红线表述

- 不说"100% 不涉及用户隐私"，说"**三层机制**：最小化 + 差分隐私 + K 匿名（可抓包验证）"；
- 不说"联邦大模型权重"，说"联邦**编排配方**（KB 级可审计资产）"。

## 七、演示与验收方案（最小闭环）

### 7.1 本地仿真（默认演示路径，单机可复现）

1. 预置 3–5 个"虚拟律所用户"（不同任务类型 / 法域 / 编辑习惯，配置化）；
2. 各自离线跑任务 → 生成各自的进化包（可展示包内容：无原文、KB 级）；
3. 同一台机器执行**真实聚合代码**（加权 FedAvg）→ 展示收敛曲线；
4. 下发新配方 → 展示可量化提升（编辑率↓ / 审计通过率↑ / 0 命中↓，前后对比表）。

### 7.2 真实小规模（进阶，2–3 台机器局域网）

- 真实客户端（法元 0.8.0 dev）各自产生任务 → 进化包经局域网 HTTP 上行 → 聚合 → 下发 → A/B；
- 价值：证明协议与代码真实可用，不是 PPT。

### 7.3 验收清单（回填式，仿 docs/09）

- [ ] 进化包 schema 校验 + 抓包确认无原文/密钥字段；
- [ ] 差分隐私加噪生效（成员推断实验：攻击者无法从聚合结果还原单用户桶）；
- [ ] <K 匿名桶被丢弃且有日志；
- [ ] 签名 manifest 校验通过才被本地采纳；篡改包被拒；
- [ ] 关闭开关/断网后：任务照常执行、指标不劣化（回归）；
- [ ] 收敛曲线 + 采纳前后指标对比表（数值回填，不写占位）。

## 十、与参赛材料的关系与使用建议
