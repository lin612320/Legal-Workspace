# 01 · 技术架构

本文档基于 `0.1.0` 版本源码整理，描述律政工作台的整体架构、分层设计与关键机制。

## 1. 总体架构

律政工作台采用 **Tauri 2 双进程架构**：Rust 后端进程 + WebView 前端。

```
┌─────────────────────────────────────────────────────────┐
│                     Tauri 桌面壳（Rust）                  │
│                                                         │
│  src-tauri/src/lib.rs                                   │
│  ├── 窗口管理：main（主窗口） / float（置顶悬浮窗）         │
│  ├── 17 个 #[tauri::command] 命令                        │
│  └── setup 阶段初始化 SQLite 连接（Mutex<Connection>）    │
│                                                         │
│  src-tauri/src/db.rs                                    │
│  └── 数据库迁移、种子数据、设置键值读写                     │
└──────────────────────┬──────────────────────────────────┘
                       │ invoke（前端发起，异步返回）
┌──────────────────────┴──────────────────────────────────┐
│                  WebView 前端（React）                   │
│                                                         │
│  src/main.tsx → App.tsx（HashRouter 路由）                │
│  ├── components/    Layout / Sidebar / Topbar           │
│  ├── views/         8 个版块页面                          │
│  ├── hooks/         useLaws / useSettings /              │
│  │                   useTemplates / useTodos（数据层）    │
│  ├── lib/tauri.ts   invoke 封装 + isTauri() 环境检测      │
│  ├── lib/ai.ts      OpenAI 兼容流式对话                    │
│  ├── lib/translate.ts 免费 / 付费翻译引擎                  │
│  └── data/          浏览器预览示例数据                     │
└─────────────────────────────────────────────────────────┘
```

### 1.1 技术选型

| 关注点 | 选型 | 理由（源码佐证） |
| --- | --- | --- |
| 桌面壳 | Tauri 2 | `tauri = { version = "2" }`，安装包体积小，前端可用任意 Web 技术 |
| 前端 | React 18.3 + TypeScript 5.5 | `react@^18.3.1`、`typescript@^5.5.0`，`tsconfig.json` 开启 `strict`、`noUnusedLocals` 等严格检查 |
| 构建 | Vite 5.4 | `vite@^5.4.0`，`vite.config.ts` 固定端口 `1420` |
| 路由 | react-router-dom 6.26 | `HashRouter`（`src/App.tsx`），适配 Tauri 文件协议 |
| 数据库 | SQLite（rusqlite 0.31，bundled） | 单文件 `legal.db`，无需外部数据库服务 |
| 时间 | chrono 0.4 | 待办 `created_at`、备份文件时间戳 |
| 序列化 | serde / serde_json | 命令返回 `Value`（JSON）给前端 |

### 1.2 目录职责

- `src/`：纯前端，与桌面壳解耦。依赖注入点只有 `src/lib/tauri.ts`。
- `src-tauri/`：Rust 桌面壳。`lib.rs` 是命令与窗口的桥接层，`db.rs` 是数据访问层。

## 2. 前端与后端通信

### 2.1 命令清单

`src-tauri/src/lib.rs` 通过 `tauri::generate_handler!` 注册了 17 个命令：

| 命令 | 分组 | 说明 |
| --- | --- | --- |
| `ping` | 通用 | 连通性测试，返回 `pong` |
| `settings_get` / `settings_set` | 设置 | 读取 / 写入单个设置键值 |
| `laws_search` | 法规 | 按关键词模糊检索条文（LIKE） |
| `templates_list` / `templates_create` / `templates_delete` | 模板 | 列表 / 新建 / 删除（内置模板拒绝删除） |
| `todos_list` / `todos_create` / `todos_update` / `todos_save` / `todos_delete` | 待办 | 列表 / 新建 / 局部更新 / 全字段保存 / 删除 |
| `backup_now` / `restore` | 备份 | 复制数据库到目标目录 / 用备份文件覆盖数据库 |
| `float_in` / `float_out` | AI 悬浮窗 | 收起为置顶悬浮窗 / 放大回主窗口 |
| `import_data` | 导入 | 预留接口，尚未实现 Excel 解析 |

### 2.2 调用封装与双环境降级

`src/lib/tauri.ts` 是唯一的桥接点：

```ts
export const isTauri = (): boolean =>
  typeof window !== "undefined" && "__TAURI_INTERNALS__" in window;

export async function callRust<T>(cmd: string, args?: Record<string, unknown>): Promise<T | null> {
  if (!isTauri()) return null;          // 浏览器预览：不调用，返回 null
  try {
    return (await invoke<T>(cmd, args)) as T;
  } catch (e) {
    console.error(`[tauri] 调用 ${cmd} 失败：`, e);
    return null;
  }
}
```

- **桌面版**：`callRust` 走 `@tauri-apps/api/core` 的 `invoke`，Rust 命令访问 SQLite。
- **浏览器预览**：返回 `null`，各 hooks 检测到后自动降级到 `localStorage` 中的示例数据。

降级策略在各 hooks 中实现（如 `useLaws.ts` 中 `isTauri() ? callRust(...) : readLocal()`）。这使 UI 开发可以完全脱离 Rust 工具链，用浏览器直接调试。

## 3. 数据层设计

- 数据库文件：`app_data_dir()/legal.db`（Windows 下为 `%APPDATA%/<identifier>` 目录，identifier 为 `com.legalworkbench.app`）。
- 连接管理：`setup` 阶段初始化连接，用 `Mutex<Connection>` 包裹后经 `app.manage()` 注入全局状态，命令内通过 `State<'_, DbState>` 取用。
- PRAGMA：开启 `journal_mode=WAL` 与 `foreign_keys=ON`。
- 迁移：`db.rs::migrate()` 使用 `CREATE TABLE IF NOT EXISTS` 幂等建表，并在表为空时播种示例数据。

表结构详见 [03-数据库设计.md](03-数据库设计.md)。

## 4. 窗口管理

`src-tauri/tauri.conf.json` 定义了主窗口，`lib.rs` 动态创建悬浮窗：

| 窗口 | label | 尺寸 | 特性 |
| --- | --- | --- | --- |
| 主窗口 | `main` | 1200 × 760（最小 980 × 680） | 居中，标题「律政工作台」 |
| 悬浮窗 | `float` | 380 × 500（最小 320 × 400） | `always_on_top`，可缩放 |

- **收起为悬浮窗**（`float_in`）：创建/显示 `float` 窗口，隐藏主窗口。
- **放大回大窗口**（`float_out`）：显示并聚焦主窗口，关闭悬浮窗。
- 悬浮窗加载 `index.html#/assistant?float=1`，`Layout.tsx` 检测 URL 上的 `float=1` 参数，渲染紧凑模式（去掉侧栏与顶栏），仅保留 AI 对话界面。

## 5. 前端内部结构

### 5.1 路由

`src/App.tsx` 使用 `HashRouter`，所有页面挂在 `Layout` 下：

```
/home 首页总览    /laws 法规查询    /templates 模板库   /assistant AI 助手
/translate 翻译   /todo 待办提醒    /settings 数据设置  /import 数据导入
```

`src/nav.ts` 集中定义 8 个导航项与当前页标题解析（`useCurrentPage`）。

### 5.2 数据层 Hooks

每个业务域一个 Hook，统一封装「桌面 SQLite / 浏览器 localStorage」双实现：

- `useLaws`：法规列表与搜索。
- `useTemplates`：模板列表、新建、删除。
- `useTodos`：待办增删改查、完成切换。
- `useSettings`：设置读取、分组写入（AI / 翻译 / 备份 / 偏好）、手动备份与还原。

### 5.3 业务能力库

- `lib/ai.ts`：OpenAI 兼容 `/chat/completions` 流式对话（SSE 解析，逐增量回调），内置三套系统提示词（通用 / 审合同 / 审质证）。
- `lib/translate.ts`：免费引擎走 `translate.googleapis.com` 的 gtx 端点（无需 Key）；付费引擎走 OpenAI 兼容接口，要求模型只输出译文。

### 5.4 样式体系

`src/styles.css`（约 1100 行）手写，无组件库。设计令牌集中在 `:root`：

```css
:root {
  --brand: #4b3fe3;        /* 主品牌色 */
  --brand-soft: #f2f7ff;   /* 选中态底色 */
  --brand-text: #1a1759;   /* 强调文字 */
  --surface / --surface-muted / --border / --text / --text-muted
  --radius: 8px;
}
```

布局采用「左侧 200px 侧栏 + 右侧主区（顶栏 + 内容）」结构，内容区为浅灰底（`--surface-muted`）卡片式布局。

## 6. 关键设计决策

1. **单机优先**：所有数据存本机 SQLite，侧栏明确标注「本地单机 · 数据在本机」，满足法律工作的数据私密性诉求。
2. **双环境可开发**：`isTauri()` 降级让前端可独立预览，降低调试成本。
3. **内置模板/条文播种**：空库自动播种，保证首次启动即可体验各版块。
4. **AI 接口可配置**：base_url 与模型名均可自定义，兼容任意 OpenAI 风格网关（如本地 Ollama、代理网关）。
