# 01 · 技术架构

> **同步至 0.6.0（2026-09-06；0.6.0 为品牌切换「法元 · Faron」，功能面同 0.5.0）**。本文档基于当前版本源码整理。产品品牌为「**法元 · Faron**」（中文名法元、英文名 Faron），工程名 / 仓库名仍为 `legal-workbench`（历史名：律政工作台 → 律衡）。0.4.0 起内置日美法律数据库（条文级 15.3 万条）并新增「文书智能体」，0.4.1 起品牌曾采用「律衡」、智能体人设命名「小衡」，0.4.2 加入「确定性引用自检」（见 CHANGELOG [0.4.2]），0.5.0 安装包 / 产品显示名曾更名「律衡」，**0.6.0 品牌切换为「法元 · Faron」、智能体人设更名「小元」**（工程名 `legal-workbench`、进程标识与数据目录 `com.legalworkbench.app` 不变）。若源码继续演进，请同步更新本文。

## 1. 总体架构

法元采用 **Tauri 2 双进程架构**：Rust 后端进程 + WebView 前端，另配一套 **Electron 悬浮球（floating-ball/）** 独立应用，通过文件桥与主程序双向联动。

### 1.1 技术选型

| 关注点 | 选型 | 理由（源码佐证） |
| --- | --- | --- |

| 系统通知 | tauri-plugin-notification 2 | 待办到期通知（`lib.rs` 后台线程轮询） |
| 前端 | React 18.3 + TypeScript 5.5 | `react@^18.3.1`、`typescript@^5.5.0`，`tsconfig.json` 开启 `strict` 等严格检查 |
| 构建 | Vite 5.4 | `vite@^5.4.0`，开发端口 `1420`（`vite.config.ts`） |
| 路由 | react-router-dom 6.26 | `HashRouter`（`src/App.tsx`），适配 Tauri 文件协议 |
| 数据库 | SQLite（rusqlite 0.31，bundled） | 单文件 `legal.db`，WAL 模式；FTS5 全文索引（trigram） |
| Excel 解析 | calamine 0.26 | `import_excel` 读取 .xlsx 导入法规 / 模板 |
| 时间 | chrono 0.4 | 待办 `created_at`、备份文件时间戳 |
| 序列化 | serde / serde_json | 命令返回 `Value`（JSON）给前端 |
| 悬浮球 | Electron 33（`floating-ball/` 独立应用） | 桌面小球 + 选词翻译/检索/AI，与主应用文件桥接 |
| 样式 | 手写 CSS | 无 UI 组件库，CSS 变量设计令牌，支持日间 / 夜间主题 |

### 1.2 目录职责

- `src/`：纯前端，与桌面壳解耦。依赖注入点只有 `src/lib/tauri.ts`（`isTauri()` / `callRust()`）。
- `src-tauri/`：Rust 桌面壳。`lib.rs` 是命令与窗口的桥接层；`db.rs` 是数据访问层；`ball.rs`、`docx.rs`、`keycrypt.rs` 分别是悬浮球集成、docx 导出、密钥混淆的独立模块。
- `floating-ball/`：Electron 悬浮球独立应用（自带 `package.json`、图标与打包配置），随主程序安装包分发。
- `src-tauri/preload/legal_preload.db`：内置日美法库预置库（git 忽略，约 467 MB），首启自动装载，不入源码库。

### 2.2 调用封装与双环境降级

`src/lib/tauri.ts` 是唯一的桥接点：

```ts
export const isTauri = (): boolean =>
  typeof window !== "undefined" && "__TAURI_INTERNALS__" in window;

export async function callRust<T>(cmd: string, args?: Record<string, unknown>): Promise<T | null> {
  if (!isTauri()) return null;          // 浏览器预览：不调用，返回 null
  try {
    return (await invoke<T>(cmd, args)) as T;
  } catch (e) {
    console.error(`[tauri] 调用 ${cmd} 失败：`, e);
    return null;
  }
}
```

- **桌面版**：`callRust` 走 `@tauri-apps/api/core` 的 `invoke`，Rust 命令访问 SQLite。
- **浏览器预览**：返回 `null`，各 hooks 检测到后自动降级到 `localStorage` 中的示例数据（`src/data/`）。
- **悬浮球桥接**：桌面模式走 Rust 命令 + `tauri` 事件（`ball-push`）；浏览器预览模式走 Vite 桥接插件 `POST /__ball_cmd__` 写控制文件（见 `vite.config.ts`），无桥接环境则静默跳过（`src/lib/ball.ts`）。

降级策略在各 hooks 中实现（如 `useLaws.ts` 中 `isTauri() ? callRust(...) : readLocal()`）。这使 UI 开发可以完全脱离 Rust 工具链，用浏览器直接调试。

### 2.3 法规检索（FTS5 / LIKE 双轨）

`laws_search` 的命令实现（`lib.rs`）与索引维护（`db.rs::ensure_laws_fts`）：

- 空关键词**不返回全量**（内置库约 15 万条 / 数百 MB），由前端引导输入。
- 关键词 ≥ 3 个字符且 FTS5 可用时，走 FTS5（BM25 相关度，先取命中 rowid 前 300，再回表按国家过滤，最终 LIMIT 500）；任何异常静默回退 LIKE。
- LIKE 回退路径对 `title / content / article_no` 做 `%kw%` 匹配，同样 LIMIT 500。
- 国家判定在 SQL 层用 `country_sql()` CASE 完成（无需迁移 / 重建预置库）：美国 = 美国法典 / 美利坚宪法标题或 govinfo / constitutioncenter 来源；中国 = 标题以「中华人民共和国」开头；日本 = e-gov.go.jp 来源；其余归为「其他」。
- FTS5 建为外部内容表（trigram 分词），由三个触发器（`laws_ai` / `laws_ad` / `laws_au`）随 `laws` 增删改同步；条文条数变化时启动重建一次索引（见 `docs/03-数据库设计.md`）。

## 3. 数据层设计

- 数据库文件：`app_data_dir()/legal.db`（Windows 下为 `%APPDATA%/<identifier>`，identifier 为 `com.legalworkbench.app`）。
- 连接管理：`setup` 阶段初始化连接，用 `Mutex<Connection>` 包裹后经 `app.manage()` 注入全局状态，命令内通过 `State<'_, DbState>` 取用。
- PRAGMA：开启 `journal_mode=WAL` 与 `foreign_keys=ON`。
- 迁移：`db.rs::migrate()` 用 `CREATE TABLE IF NOT EXISTS` 幂等建表，并用 `ensure_column` 幂等补列（`documents`、`todos.last_notified_due`、`chat_messages.session_id` 等历史兼容迁移）；空表时播种示例数据。
- 内置法库装载：首启时若 `legal.db` 不存在、或 `laws` 仅剩播种示例（≤ 6 条），会自动从预置库多路径（Resource / exe 同目录 / 浅层扫描）拷贝装载；旧空库先备份为 `legal.db.user-<时间戳>.db`（`lib.rs::setup`）。
- API Key 落盘：`ai.api_key` / `translate.api_key` 经 `keycrypt.rs`（与前端 `secret.ts` 对称的 XOR+hex）混淆存储，带 `enc:` 前缀；启动时把历史明文幂等迁移为密文（`migrate_secret_keys`）。

全部表（settings、laws、templates、todos、documents、chat_sessions、chat_messages、tasks、task_steps、task_artifacts、mem_vectors）及 FTS5 虚拟表 `laws_fts` + 三个触发器的结构详见 [03-数据库设计.md](03-数据库设计.md)。

## 4. 窗口管理

`src-tauri/tauri.conf.json` **预声明**两个窗口（不运行时动态建窗，规避 Windows 上二次 `build()` 挂起/空白的历史问题）：

| 窗口 | label | 尺寸 | 特性 |
| --- | --- | --- | --- |
| 主窗口 | `main` | 1200 × 760（最小 980 × 680） | 居中，标题「法元」 |
| 置顶悬浮窗 | `float` | 380 × 500（最小 320 × 400） | 标题「AI 问答 · 悬浮」，`alwaysOnTop`，启动即创建、默认隐藏，`skipTaskbar` |

- **收起为悬浮窗**（`float_in`）：显示并聚焦 `float`，隐藏主窗口。
- **放大回大窗口**（`float_out`）：显示主窗口（`unminimize` + 聚焦），隐藏 `float`。
- **关闭悬浮窗 = 收起**：`lib.rs` 为 `float` 窗口拦截 `CloseRequested`（`prevent_close`），改为隐藏悬浮窗并恢复主窗口。
- 悬浮窗加载 `index.html#/assistant?float=1`，`Layout.tsx` 检测 URL 上的 `float=1` 参数渲染紧凑模式（去掉侧栏与顶栏），仅保留 AI 对话界面。
- 系统通知：`lib.rs` 末尾启动后台线程，每 30 秒调用一次 `check_todo_notifications`，对「未完成 + 桌面弹窗开启 + 有到期时间 + 该到期时间未提醒过」的待办发系统通知，并回写 `todos.last_notified_due` 避免重复提醒。

## 5. 前端内部结构

### 5.1 路由

`src/App.tsx` 使用 `HashRouter`，所有页面挂在 `Layout` 下：

```
/home 首页总览    /laws 法规查询    /templates 模板库   /assistant AI 问答
/agent 文书智能体 /translate 翻译   /todo 待办提醒      /focus 专注计时
/settings 数据设置 /import 数据导入
```

`src/nav.ts` 集中定义 **10 个导航项**（`NAV_ITEMS`）与当前页标题解析（`useCurrentPage`）。未匹配路径重定向到 `/home`。

### 5.2 数据层 Hooks

每个业务域一个 Hook，统一封装「桌面 SQLite / 浏览器 localStorage」双实现：

- `useLaws`：法规总数与按需关键词检索（桌面不下发全量条文）。
- `useTemplates`：模板列表、新建、删除。
- `useTodos`：待办增删改查、完成切换。
- `useSettings`：设置读取、分组写入（AI / 翻译 / 备份 / 偏好）、API Key 混淆、手动备份与还原。
- `useDocuments`：最近文书（智能体交付物落点）列表、刷新与删除。

### 5.3 业务能力库

- `lib/ai.ts`：OpenAI 兼容 `/chat/completions` 流式对话（SSE 逐增量回调）+ function calling（`tool_calls` 累积解析）+ 结构化输出请求；内置「通用 / 审合同 / 审质证」三套系统提示词。
- `lib/agent.ts`：文书智能体引擎——`planTask`（模型结构化规划 → 可编辑计划卡）/ `executeStep`（一步一停，工具步骤与推理步骤分流）/ `runAgenticToolStep`（模型驱动工具循环 ≤ 6 轮）/ `runReasoningStep`（按角色 system 提示词）；**确定性引用自检**（`extractCitationTokens` / `auditCitations` / `auditReport`，规则级校验，非模型自述）；`composeDeliverable` 合成 Markdown 交付物；`deliverTask` 桌面导出 .docx + 落库 / 浏览器下载 .md；记忆 `rememberTask` / `recallMemory`。
- `lib/tools.ts`：智能体工具注册表（`laws_search` / `law_by_id` / `laws_country_preview` / `template_load` / `translate_text`），结果统一 `ToolResult`，带 `refs`（真实法条引用，可溯源展示）。
- `lib/translate.ts`：免费引擎（Google gtx，无需 Key）+ 付费引擎（OpenAI 兼容接口，模型直接输出译文）。
- `lib/ball.ts` / `lib/open.ts` / `lib/secret.ts` / `lib/embed.ts`：悬浮球调用、交付物打开定位、密钥混淆、向量化与余弦相似度。

### 5.4 样式体系

`src/styles.css` 手写，无组件库。设计令牌集中在 `:root`，夜间模式通过 `document.documentElement.dataset.theme = "dark"` 切换并持久化到 localStorage（键 `workbench:theme`，由 `Topbar.tsx` 控制）。布局为「左侧侧栏 + 右侧主区（顶栏 + 内容）」的卡片式布局。

## 6. 关键设计决策

1. **单机优先**：所有数据存本机 SQLite，侧栏明确标注「本地单机 · 数据在本机」，满足法律工作的数据私密性诉求。
2. **双环境可开发**：`isTauri()` 降级让前端可独立预览（`src/data/` 示例数据），降低调试成本。
3. **内置模板 / 条文播种 + 预置法库**：空库自动播种保证可用；正式安装包内嵌日美法库预置库，首启自动装载，装机即用（旧空库先备份再覆盖）。
4. **AI 接口可配置**：base_url 与模型名均可自定义，兼容任意 OpenAI 风格网关（如本地 Ollama、代理网关）。
5. **检索按需 + 双轨**：法规库达 15 万条，绝不挂载即全量拉取；FTS5 优先（≥ 3 字关键词）、LIKE 兜底，任何索引异常不阻塞主流程。
6. **智能体引用可溯源**：工具只返回本地库真实条文（`refs`），模型被强制「只引用工具真实返回」；交付物再叠加确定性引用自检（见 Unreleased），未覆盖引用点名提示人工核实。
7. **悬浮球进程解耦**：主程序启动自动以子进程拉起 Electron 悬浮球（`CREATE_BREAKAWAY_FROM_JOB`，失败去标志重试），命令经控制文件下发而非二次进程传参，避免便携版/打包 exe 参数透传不可靠的问题。
