真实法库 · 条文级检索

152,940 条日美法条文开箱即用，SQLite FTS5 全文检索 + 按法浏览 + 双语标题 + 条文跳转。

展开细节 ▾
  • 按国家进入专属页：政体 / 法律体系概览 + 按领域分组的法律清单
  • 整部法浏览页：阿拉伯数字 / 中文数字 / 罗马数字条文号一键跳转
  • 正文可选中复制，一键打印或另存 PDF
  • 中文关键词检索：命中译名与译文正文，无命中自动回退模糊匹配

确定性引用自检

规则级校验，不让模型自己检查自己：抽取正文里的条文号，逐一与检索工具真实返回的法条比对。

展开细节 ▾
  • 未被工具实际覆盖的引用会被自动点名，交付前就能发现
  • 再叠加一层图谱适用性校验：引用的法律名是否落在该案由的请求权基础范围内
  • 自检结论写进交付物，客户与合议庭都能看到依据

知识图谱规划

案由 → 构成要件 → 请求权基础 / 证据 / 争点 → 文书载体，骨架驱动计划卡，防止要件遗漏。

展开细节 ▾
  • 5 类固定关系：构成要件是 / 请求权基础是 / 证明对象是 / 常见争点是 / 文书载体是
  • 任务中真实命中的法条登记为候选边，人工 ✓ / ✕ 确认后才作为规划依据
  • 法条节点只存"法律名"，不写具体条号，避免机器编造

文书智能体 · 5 类任务

合同审查 / 起诉状 / 证据目录 / 质证意见 / 代理词，每类有独立输出骨架与人工确认闸门。

展开细节 ▾
  • 计划卡可人工编辑后再执行，一步一停、支持暂停与续跑
  • 检索类步骤走自主工具调用循环，只引用工具真实返回的法条
  • 执行日志逐条可查，历史任务可载入续跑

多模态任务材料

DOCX / PPTX / XLSX / TXT / MD / CSV 本地离线提取；PDF 与图片交给视觉模型转录并明确标注"非原文"。

展开细节 ▾
  • 自研最小 ZIP 解析，不依赖外部转换服务，材料不出本机
  • 单文档 20 万字符上限并按 UTF-8 边界安全截断
  • 模型转录文本不进入原文引用口径，避免"机器转述"被当成证据

交付闭环

智能体产出 → 导出 .docx（原生标题与表格）→ 落入首页「最近文书」→ 一键用系统程序打开或定位。

展开细节 ▾
  • 证据目录等表格型交付直接渲染成 Word 原生表格
  • 浏览器预览形态下降级为 .md 下载，能力边界显式提示
  • 翻译成果同样可导出 Word / Markdown 并记入最近文书

引用自检实验室

亲手注入一个假条号，看它被抓出来

这是本产品与其他 AI 助手最本质的区别：引用由规则逐条比对本地库，而不是让模型"自查一遍"。

交付物节选 · 法律适用部分

本案系涉外合资经营合同纠纷，日方逾期未出资且拒不召开董事会。 依《中华人民共和国民法典》第五百零二条关于合同生效之规定， 合同已依法成立并生效；就日方迟延履行， 日本民法第 415 条规定债权人可请求损害赔偿； 另参美国法典 Title 15 § 1125关于商业标识之规定， 结合本案事实，我们认为日方应承担出资违约责任并赔偿相应损失。

校验逻辑：抽取正文引用 → 解析「法名 + 条号」→ 与上方「法规检索工作台」的同一份本地库比对； 库里没有的条号一律判为编造。想亲手检索这些条文，去上面的检索台试试。

差异对比

通用 AI 助手 vs 法元

同一条提示词，差别不在"文笔"，而在法条从哪来、数据放哪、能不能交出去。

? 通用 AI 助手

  • · 法条来自模型记忆，条号正确性无法核验
  • · "自查一遍"仍是模型自述，没有独立校验
  • · 案件材料必须上传到别人的服务器
  • · 输出一段文字，格式与交付文件要手工重排
  • · 没有结构化案由 / 要件 / 证据管理
  • · 检索能力取决于对话窗口，无法按法浏览

  • ✓ 数据全在本机 SQLite；仅调用你自己配置的模型接口

检索类步骤只从本地库返回真实条文，模型无权凭空写入；交付物还要经过确定性引用自检（逐条号比对工具返回值）与图谱适用性校验；图谱中的法条节点只保存"法律名"，不写具体条号。三重约束就是为了防编造。
DOCX / PPTX / XLSX / XLS / TXT / MD / CSV / LOG 本地离线提取文本（单文档上限 20 万字符）；PDF 与图片需要配置支持文件或视觉输入的模型来转录，转录文本会明确标注「模型转录，非原文」，不进入原文引用口径。
